PRD-HABIT-CHECKIN · v0.4.0

儿童日常习惯打卡

孩子完成日常习惯 → 三选一获得食物卡 → 喂养档案内的小伙伴 → 看见成长。本功能绑定 ChildProfile，提升日活与粘性；奖励归属孩子档案，与账户积分体系完全隔离。

1. 目标、用户与场景

1.1 产品目标

  • 增长目标：提升启用打卡家庭的 D7 留存、周活跃打卡天数与日打开频次。
  • 体验目标：使用者愿主动点开、完成有趣、喂养有回应；60 秒内可完成一名孩子的习惯配置。
  • 教育边界：认识食物与多样膳食，不承诺改善身高/BMI/挑食，不做个体喂养建议。

1.2 北极星

首喂养用户的 D7 再喂养率（第 0 天完成首次喂养的 ChildProfile 中，第 7 天再次喂养的比例）。辅看：周打卡天数、选卡→喂养完成率。

1.3 核心场景卡片

场景 A · 晚间刷牙后打卡

4 岁孩子「小禾」晚饭后刷牙，打开产品，从首页紫色入口进入打卡页，点「认真刷牙」，弹出三选一食物卡，选「奶类」后去花园喂「小芽」，看到成长值 +2。

场景 B · 首次配置

使用者在「我的 → 孩子档案」为小禾启用刷牙、收玩具、阅读 3 个习惯；洗澡等暂不启用。也可自定义一个「说晚安」习惯（每晚 1 次）。打卡页只展示已启用任务。

场景 C · 兄弟姐妹切换

同一账户下哥哥「豆豆」与妹妹「小禾」各有独立习惯计划、背包、成长值。切换档案后数据完全隔离，不串档。

场景 D · 0–2 岁共同体验

打开孩子档案后，用大图标完成点选并一起观看反馈；页面强调「食物认知游戏，不是喂养建议」。不要求低龄儿童独立理解规则。

2. 已确认决策（冻结）

D5成长属于孩子档案更换伙伴外观不清零成长值、卡册、花园。
D6首期不与故事联动无故事 CTA、无故事参数写入、无听故事自动点亮强耦合（「听故事」仅在当前业务日手动打卡，不支持补签）。

4. 信息架构与主流程

4.1 入口（不改一级导航）

位置形态规则
首页带今日进度的伙伴入口卡（原型紫色大卡）展示当前有效孩子档案的「今日 x / n」与待处理奖励数；点击进打卡页。
独立打卡页/habits（建议路由名，可按工程约定微调）任务卡 + 完成动画 + 领卡弹层。
伙伴花园页/habits/companion喂养、摸头、成长档案弹层。
我的 → 孩子档案档案卡增加「习惯管理 / 成长记录」与打卡页使用相同登录态和权限；不增加家长门或角色判断。

4.2 主流程

【首次配置】我的 → 孩子档案 → 习惯管理 → 选 1–3 个模板或自定义 → 保存 【每日打卡】首页入口 →（多孩则选档案）→ 打卡页 → 点当前可用 slot 完成 → 专属动画 → 若当日奖励次数<3：弹出三选一 → 选卡入背包 → 「去喂养」→ 花园页 → 喂养 → 成长反馈 【恢复任务】关闭弹层或跨天返回 → 首页/打卡页查看“待选” → 花园查看“待喂” → 继续原状态 【误点纠正】习惯管理 / 成长记录 → 撤销当日误点 → 未喂养卡回收；已喂养写冲正 → 同一 slot 可重新完成

4.3 核心循环（产品形态）

完成习惯 → 三选一食物卡 → 拖/点喂养 → 伙伴即时回应 → 营养环点亮 → 阶段成长。

5. 习惯打卡规则

5.1 官方模板（6）

templateKey默认名频次时段位完成反馈
brush认真刷牙每天 2 次morning / evening牙齿由灰变亮、冒泡
bathe洗澡或洗漱每天 1 次daily浴缸泡泡升起
tidy收好玩具每天 1 次daily玩具跳回收纳箱
read今日阅读每天 1 次daily点亮一本书（不强制页数）
story听一个故事每天 1 次daily手动打卡；首期不做播放自动点亮强依赖
bedtime按时睡觉每天 1 次daily（睡前窗口）点击「我准备睡觉啦」；无需睡着后操作

5.2 自定义习惯

  • 名称 2–12 字；选图标；频次仅 daily 或 morning+evening。
  • 在习惯管理页配置；打卡页只展示已启用任务卡。
  • 内容安全：长度校验 + 敏感词/风险意图过滤；命中时提示改写，任何页面都不展示未通过原文。

5.3 启用数量与完成位

  • 建议同时启用 1–3 个；产品可 soft-limit 提示，硬上限建议 ≤ 6（防配置爆炸）。
  • 进度按 slot 计算：启用刷牙（早/晚）+ 收玩具 + 阅读时，分母为 4，不是 3。
  • 刷牙卡固定展示「早 / 晚」两个状态；服务端按当前时间自动命中唯一可打 slot，客户端选择仅作为期望值校验。
  • 唯一键：(childProfileId, childHabitId, localDate, slot) 永远只有一条业务记录；撤销后重新完成复用该记录。
  • 动画可重播；业务完成与奖励不可重复结算。

5.4 业务日期、时区与时段

  • MVP 固定时区：Asia/Shanghai。时区由服务端配置；本期不跟随设备、不提供用户修改。每条日期敏感记录均快照 timezone。
  • 业务日边界：当地时间 04:00 换日；服务端以 localDate = date(now in timezone - 4h) 计算。00:00–03:59 自动归入前一业务日。
  • 时段窗口：morning 04:00–11:59；daily 04:00–次日 03:59；evening 17:00–次日 03:59；bedtime 18:00–次日 03:59。区间左闭右开，以服务端接收时间为准。
  • 窗口外：拒绝写入并返回 SLOT_NOT_OPEN，界面展示下一可用时段；不得自动写入另一个 slot。
  • 客户端可提交 expectedLocalDate/expectedSlot 用于漂移提示，但不能决定日期、时段、奖励次数或成长上限。
  • 首期不支持补签/补记。过期 slot 只读，不提供任何操作者的回填入口。

5.5 撤销

  • 任何登录使用者都可从历史页撤销当前业务日误点；超出当前业务日只读。
  • 若对应奖励尚未喂养：回收候选/已选未喂卡，打卡与 grant 置 REVOKED。
  • 若已喂养：不删历史，写唯一冲正记录；成长值、营养属性与当日彩虹奖励按快照回滚，数量不得小于 0；highestStage 与已解锁里程碑不回收。
  • 撤销后允许在窗口内重新完成：复用原 HabitCheckIn 并使 version + 1，不插入第二条；原 grant 若存在则复用原 dailyRewardIndex 与三张候选，避免撤销刷卡。
  • 完成、撤销、重新完成都写操作日志；重复撤销或重复提交返回当前状态，不重复回滚或发奖。

术语：儿童获得的是「食物卡」；卡携带 1–3 个「营养属性」游戏点。属性点≠真实含量、≠摄入量、≠每日推荐量。界面必须标注游戏数值说明。

6.3 奖励发放

  1. 每个有效完成（唯一键首次成功）触发奖励资格判断。
  2. 每天最多 3 次食物卡奖励（按 childProfileId + 服务端 localDate）。第 4 次及以后：仍有庆祝动画与历史记录，但不掉落候选卡。
  3. 打卡写入与奖励名额占用在同一事务中完成；grant 获得 dailyRewardIndex=1|2|3，数据库唯一约束保证并发时不会产生第 4 份。
  4. dailyRewardIndex 一经分配即为该业务日保留，撤销后不转让给其他 check-in；重新完成原 slot 时复用原 index 与候选，避免通过撤销刷新奖励。
  5. 有资格时幂等创建 CheckInRewardGrant，生成 3 个互不相同的 cardKey；至少 1 张补齐当前最弱属性。
  6. 选 1 张 → 入背包（ChildFoodCard.quantity++）；图鉴首次发现记 discoveredAt。同一 grant 重试只返回已有选择。
  7. 所有首发卡同等级；无付费、无稀有概率。

6.4 待选、待喂与恢复

  • grant 状态机：PENDING_SELECT → SELECTED → FED；当前业务日撤销可从前三态进入 REVOKED；已喂养撤销同时生成 REVERSED feed record。
  • MVP 不设 EXPIRED。待选、待喂均可跨天保留，不静默过期、不因灰度关闭丢失。
  • 首页和打卡页展示「N 张待选择」；花园展示「N 张待喂养」。再次进入先恢复最早创建的未完成 grant，可逐张处理，也可暂时关闭。
  • 用户连续完成 3 次后可以统一选卡、统一喂养；列表按 createdAt ASC 排序，状态写入必须由服务端校验合法迁移。
  • 背包不设 30 张上限，按 childProfileId + cardKey 聚合数量；数量扣减用条件更新，永不小于 0。

6.5 喂养、彩虹餐盘与成长上限

  • 喂养 1 张卡：+2 成长值；累加对应营养属性。
  • 「彩虹餐盘」仅统计当前时区、当前业务日内未冲正的喂养记录所覆盖的不同营养属性；首次达到 ≥4 类时额外 +2，每个业务日最多触发一次。
  • 每日成长值上限 8，包含基础成长和彩虹奖励。喂养前由服务端预演；若本次完整增量会超过 8，则不扣卡、不写营养、不写成长，返回 DAILY_GROWTH_CAP，提示「今天成长值满啦，小卡已保存，明天再来喂」。
  • 重复卡可继续喂；图鉴只记第一次。
  • 一份 grant 只能喂一次；事务：校验上限 → 条件扣卡 → 加属性 → 加成长 → 计算彩虹 → 触发里程碑 → 写服务端埋点。
  • 冲正后若当日不再满足 4 类，彩虹 +2 同步回滚；growthValue 可下降，但 highestStage 单调不下降、里程碑不回收。

6.6 阶段门槛

阶段growthValue解锁
1 初见伙伴0–19眨眼、跟随；名字牌
2 活力幼崽20–59体型长高一格；摸头、开心转圈
3 好奇伙伴60–139房间角落探索；第一件装扮
4 探险伙伴140–299花园探索动作；新表情

升级同时要求营养环至少点亮 4 类。界面用环形拼图，禁止「缺铁」「营养不良」等诊断文案。数值溢出不产生暴击或「真实长高」。

6.7 伙伴互动（首期）

  • 轻触摸头：短反馈，不发奖励，防连点刷。
  • 喂养：核心反馈 1.5–2.5s（抛物线入口袋/碗 + 咀嚼/眨眼 + 一句台词）。
  • 状态待机：未打卡整理花园；完成跳跃；全完成撒花。永不饥饿/哭泣/生病/离家。
  • 夜间：睡前时段花园变暗、打哈欠；轻触挥手后安静待机。
  • 缺席回流：只说「欢迎回来」，不展示断签损失。

6.8 伙伴初始化与外观目录

正式养成：cat / dog / rabbit / frog（原创）/ astronaut（原创）/ custom。custom 仅表示“从上述原创外观中选底模并自定义名称”，首期不支持上传图片或自由组合素材。

  • 首次读取 companion 或首次启用习惯时，服务端幂等创建 CompanionGrowth，childProfileId 唯一。
  • 若孩子档案的故事伙伴可安全映射为 cat/dog/rabbit，则沿用物种；芭比娃娃、奥特曼及无法识别的旧数据统一使用 rabbit 默认外观，不映射同名角色。
  • 默认名称为「小芽」；appearanceKey 与故事 partnerJson 完全分离，后续换外观不影响故事资料。
源码对齐任务：现有 PARTNER_PRESETS 含芭比娃娃/奥特曼，仅可用于故事创作选角，不得作为本养成系统的持久外观素材，直至授权明确。故事伙伴 JSON 与 CompanionGrowth.appearanceKey 可并存，但养成页只读成长档案外观。

8. 页面规则（v0.4.0 规格）

原型同步：v0.4.0 已覆盖首页 → 双 slot 打卡 → 关闭后恢复选卡 → 喂养 → 成长档案，以及习惯管理、历史撤销、页面壳层和统一使用者文案。

8.1 首页入口卡

  • 文案示意：「今天也来打个卡吧」+ 「完成小习惯，带食物去看小芽」。
  • 进度 pill：今日 x / n（n = 今日应完成 slot 总数，含早晚拆分）；刷牙 + 收玩具 + 阅读示例显示 0 / 4。
  • 存在未完成奖励时展示「N 张待选择 / N 张待喂养」角标，点击后恢复最早一条。
  • 右侧展示当前伙伴形象；不改首页故事主 CTA 与 BottomNav。
  • 默认档案先读取浏览器本地“上次选择”（按 userId 隔离）并向服务端校验；无效或被软删除时选择最近更新的有效档案。多孩首次进入先展示档案选择器。
  • 未登录点击入口走现有登录拦截；无有效档案时进入现有新建孩子档案流程；不创建账户级 defaultChild 字段。

8.2 打卡页

  • 顶栏：返回、标题「今日成长打卡」、孩子切换 chip。
  • 日卡：日期 + 问候 + 进度条。
  • 任务网格：大点击区；未启用模板灰色占位（「还没有加入今天计划」）。
  • 刷牙卡内展示早/晚两个 chip；当前可打位高亮，已完成位打勾，未到时位展示时间。早晚均完成后整卡完成。
  • 单项完成：stamp 变绿 + 庆祝动画；重复点击 Toast「这个时段已经打过卡啦」；窗口外 Toast 展示下一开放时间。
  • 领卡 Overlay：三选一 → 营养说明卡（含游戏数值免责）→ 「去喂养」。
  • Overlay 可关闭；顶部保留待选择入口。三次连续完成可积累 3 条待选择，不强迫逐次喂养。

8.3 花园喂养页

  • 全屏花园背景 + 居中伙伴；顶栏成长迷你条。
  • 底部 feed-dock：按最早创建顺序展示待喂卡和总数 + 「喂给小芽」；每日成长达上限时按钮禁用但卡保留。
  • 点击伙伴 → 成长档案弹层（阶段、成长值、6 营养条、归属说明）。

8.4 习惯管理与历史

  • 启用/停用官方模板；编辑自定义；查看日历式历史。
  • 当前业务日的已完成记录可撤销；撤销后在对应窗口内可重新完成。
  • 说明：奖励是游戏、非医疗；允许休息、成长不清零。
  • 与打卡页共用登录与 ChildProfile 所有权校验；不显示“家长侧/儿童侧”，不设 PIN、长按或身份切换。

8.5 页面壳层

/habits、/habits/companion 与习惯管理页采用沉浸式业务壳层：隐藏全局 Header 和 BottomNav，仅保留页面返回/关闭；首页与其他现有页面壳层不变。工程实现需用路由分组或可判定路由的 Shell，禁止同页重复两套顶栏。

9.3 关键约束

  • idempotencyKey 为 UUID 字符串，最长 64 字符，唯一作用域为 childProfileId + operation；由 HabitCommand 连同响应快照长期保留，不做定时清理。打卡、选卡、喂养、撤销各使用独立 key。
  • 打卡与奖励名额占用同事务；选卡、喂养、撤销分别服务端幂等；客户端重试不得重复发奖、扣卡或冲正。
  • 兄弟姐妹：所有查询强制 childProfileId + 当前 user 所有权。
  • 档案软删除：停用 ChildHabit；历史保留；恢复后可继续。
  • FoodCardDefinition 版本化：发放时快照 nutrientDelta，避免改表影响历史。
  • 关键数量使用数据库条件更新；ChildFoodCard.quantity、growthValue 与各营养属性不得小于 0。
  • 状态变化只允许服务端状态机迁移；成功埋点在事务提交后写入。客户端不得提交 userId、最终 status 或“成功”结论。
  • 复用现有 OperationEvent 记录完成、撤销、重新完成、选卡、喂养、冲正；不记录自定义习惯原文和儿童昵称。

10.1 候选卡算法（服务端）

  1. 读取 CompanionGrowth.nutrientStateJson，找当前最低属性（并列随机）。
  2. 从 enabled 卡池抽 3 张互不相同的 cardKey：至少 1 张对该属性 delta > 0；其余从剩余卡池随机。
  3. 不向客户端返回权重分数或「你缺钙」类文案。

13. 非功能需求

  • 移动端优先：375px 可用；安全区；尊重 prefers-reduced-motion。
  • 性能：常规网络下今日任务读取 P95 ≤ 500ms，打卡/选卡/喂养 API P95 ≤ 800ms（不含客户端动画）；动画资源失败时降级为静态成功反馈。
  • 安全：所有写接口鉴权 + ChildProfile 所有权；自定义名称内容过滤。
  • 合规：儿童个人信息走既有档案同意；营养内容免责声明；不构成医疗建议。
  • 灰度：使用 hash(userId + flagVersion) % 100 稳定分桶，支持管理员紧急关闭。关闭后禁止新打卡/新 grant，但保留历史只读、撤销纠错与已有待选/待喂处理。
  • 隔离：不改动故事生成、积分交易、BottomNav 核心结构。
  • 测试基建：在业务开发 P0 内建立单元/接口测试；SQLite 覆盖唯一约束竞争、写锁等待、事务失败重试，水平扩容前重新评估数据库。
  • 隐私：分析系统限制儿童档案标识访问；不记录昵称、自定义习惯原文、候选文案或其他儿童内容。

14. 验收标准

14.1 习惯

  • 任一登录使用者 60 秒内可为一名孩子完成官方或自定义配置；没有家长/儿童角色入口或权限差异。
  • 从首页进入后，单项打卡 ≤ 2 次有效点击完成。
  • 刷牙 morning/evening 两位独立并在卡内可见；刷牙 + 收玩具 + 阅读的首页进度为 0/4；同键重复不双计。
  • 服务端按 Asia/Shanghai 与 04:00 换日计算 localDate；00:00–03:59、窗口外、客户端改时间与多设备漂移用例通过。
  • 首期不存在补签入口；撤销复用原记录，窗口内可重新完成且不改变原三张候选。
  • 切换兄弟姐妹后任务、连续展示、奖励、成长不串档。
  • 自定义违规名无法保存；任何页面都看不到未通过文本。

14.2 奖励与养成

  • 同一 checkIn 串行、并发、超时重试不会产生第二条完成或第二份候选。
  • 两台设备并发争抢当天第 3 份奖励时，最多一份占用 index=3，数据库中不存在 index=4。
  • 每日第 4 次完成有动画无掉落。
  • 每份三选一的三个 cardKey 互不相同，且至少含一张补齐最弱属性的卡（可用固定夹具测）。
  • 关闭弹层、跨业务日、多张积压后均可恢复待选/待喂；背包不设 30 张上限。
  • 同一 grant 并发喂养只成功一次，卡数量不小于 0；每日上限前预检，失败不消费卡。
  • 彩虹餐盘只按当日未冲正 feed 统计；冲正可撤销彩虹/growth/营养，但 highestStage 与里程碑不下降。
  • 换外观后 growth/图鉴/里程碑保留。
  • 伙伴无生病/断签惩罚文案；页面有游戏数值免责说明。

14.3 体验与回归

  • 主路径：首页 → 打卡 → 选卡 → 喂养 → 成长弹层，与高保真原型 v0.4.0 一致。
  • 打卡、花园、习惯管理隐藏全局 Header/BottomNav 且保留页面返回；首页和故事主链路回归通过。
  • 0–8 岁共用同一主界面；375px、安全区、键盘/读屏标签与 prefers-reduced-motion 通过。
  • 未登录、无档案、上次档案被删除、多孩首次进入与本地默认档案回退用例通过。
  • 弱网可重试；未喂撤销、已喂冲正、重复撤销与软删除恢复符合第 5.5 / 9.4 / 11 节。
  • 灰度关闭时新写入被拒绝，历史/撤销/既有待处理奖励仍可完成；积分余额不被本功能改动。
