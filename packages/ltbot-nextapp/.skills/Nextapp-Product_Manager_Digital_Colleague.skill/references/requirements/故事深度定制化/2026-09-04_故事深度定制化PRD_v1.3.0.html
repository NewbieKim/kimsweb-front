PRD-CUSTOM-2026-09 · v1.3.0

故事深度定制化改造

第二期详细方案：将“真人照片”收敛为私密的自定义头像图片；故事不经过人工前置审核，用户确认后同步公开并直接进入故事广场。

状态：第二期产品方案已确认，待技术与上线合规评审 ｜ 创建：2026-09-04 ｜ 更新：2026-09-05 ｜ 当前唯一开发契约

1. 评审结论（v1.2.1 → v1.3.0）

评审方 / 意见结论吸收方式
产品负责人：不限制为“真人照片”，用户喜欢什么图片都可作为头像。采纳统一命名“自定义头像图片”。不识别人脸、不要求真人主体；仅限制安全文件格式、大小与合法使用。头像作为家庭私密资产，不进入广场，也不用于图生图。
产品负责人：当前不设审核，发布后直接进入广场。采纳，补充安全底座删除 PUBLIC_PENDING、审核中/通过/驳回和人工审核队列。用户确认后由 PRIVATE 同步变为 PUBLIC。保留生成阶段机器安全结果、发布前隐私校验、公开后的举报与一键下架；它们不是人工前置审核。
原方案：审核通过发 5 积分。不吸收 / 本期砍掉无审核通过事件后不存在可靠发奖节点，直接发奖会诱导批量公开和刷广场。公开奖励独立评审，本期公开不加分。
原方案：公开时沿用完整私密故事与孩子头像。不吸收孩子昵称、生活片段和自定义头像属于高风险信息。广场只读“公开安全快照”，以公开称呼替换孩子昵称并过滤可识别细节；私密原文不变。
一句话方案：头像可以自由选图，但只在自己的家庭空间里使用；故事可以一键公开，但公开的是脱敏后的广场版本，不经过人工等待。

2. 产品现状与约束

现状证据对第二期的影响
创作页已有 input type=file 和 Blob 预览，但图片只存在当前浏览器，未上传、未持久化。不能把当前“上传头像”视为已完成功能；需补齐私有对象存储、处理、授权读取与删除生命周期。
当前工作区已开始加入 StoryVisibility、ChildProfile 与 StoryCustomization 的一期数据模型，但仍无 publishedAt，故事列表/详情接口也尚未完成公开与所有权分流。第一期数据迁移可以复用；访问策略仍必须先完整落地，否则“私密”和“公开”只是 UI 文案。
探索故事 / 故事广场、故事详情、点赞、收藏、评论、分享已存在。第二期复用既有入口和页面，不新增一级导航、底栏或新广场路由。
故事由平台 AI 生成，封面/插画也来自平台生成链路；用户自定义素材可能被织入正文。不需要给用户搭建复杂投稿审核，但必须防止昵称、学校、地点、联系方式等随着正文被公开。
当前没有头像对象存储、故事发布/撤回、举报或审核相关接口。按“最小可上线闭环”新增，不建设独立审核后台和审核角色体系。
P0 前置：第一期的 PUBLIC / PRIVATE 访问策略、所有权校验、私密字段日志脱敏完成并回归通过后，第二期公开入口才能灰度。

3. 用户、场景与目标

场景 A · 自定义头像

3—6 岁孩子的家长在晚间创作前，希望用孩子照片、卡通画、宠物或任何喜欢的图片标记档案，之后能一眼选对“今晚讲给谁”。家长不希望这张图自动出现在公共页面。

场景 B · 公开故事

家长完成一个满意的故事后，愿意把故事分享给其他家庭，希望点击发布后马上在广场看到，不想等待审核，也不想理解“待审、通过、驳回”等状态。

3.1 产品目标

  • 让自定义头像真正可跨设备复用，而不是一次性的本地预览。
  • 把“私密创作 → 自愿公开 → 广场发现 → 随时撤回”做成低心智闭环。
  • 公开发布不暴露孩子头像、档案、今晚小事原文或可识别的生活细节。
  • 不引入人工前置审核的人力、排班、审核 SLA 与状态机。

3.2 成功指标

指标目标 / 口径
发布即时性发布接口成功后 P95 ≤ 2 秒进入 PUBLIC，广场首屏刷新可见；不出现“审核中”。
隐私泄漏公开 API、页面源数据、日志中自定义头像对象 key、今晚小事原文、ChildProfile 字段泄漏数 = 0。
头像成功率合法格式图片从选择到 READY 成功率 ≥ 98%，P95 处理时长 ≤ 5 秒。
撤回即时性转为私密后 P95 ≤ 2 秒从广场/公共详情失效，缓存最迟 60 秒内清除。
产品验证观察生成完成 → 发布点击率、确认完成率、7 日撤回率与举报率；上线初期不设虚假增长承诺。

6. 自定义头像图片

6.1 定位与展示边界

  • 字段名和界面文案统一为“自定义头像”或“上传图片”，不得出现“真人照片”。
  • 可上传人物照片、插画、卡通、宠物、风景等；不做人脸检测、不要求正脸、不判断是否真人。
  • 仅用于登录用户自己的档案选择、生成中提示、私密回执和本人私密故事详情。
  • 不得显示在故事广场、公共故事详情、分享卡片、评论区或其他用户可访问的响应中；不得作为插画生成输入。

6.2 文件规则

项目规则失败文案
格式JPEG、PNG、WebP；仅静态图。以前端 accept 提示、服务端魔数、真实 MIME 和实际解码四重校验，不信任扩展名。“暂不支持这类图片，请选择 JPG、PNG 或 WebP。”
大小源文件 ≤ 5 MB；解码尺寸 128×128 至 8192×8192；总像素 ≤ 32 MP，防止解压炸弹。“图片太大或太小，请换一张再试。”
裁切客户端提供 1:1 裁切、缩放和旋转；服务端按裁切参数再次处理，输出 512×512 WebP。“图片处理失败，请重新裁切或换一张。”
元数据处理时按 EXIF Orientation 校正方向；输出文件移除 EXIF/GPS/设备信息与原文件名。无需暴露技术原因。
内容权利首次上传前单独勾选：“我确认有权使用这张图片；如包含儿童信息，我是其监护人或已获得监护人授权。”拒绝不影响使用预设头像和核心创作。未确认时不发起上传。

6.3 存储、替换与删除

  • 源文件先进入私有 tmp 区，处理成功后只保留标准化成品；源文件最迟 1 小时自动清理。
  • 成品存放私有 Bucket，数据库只存内部对象 key；读取必须鉴权并签发短期 URL（建议 5 分钟），禁止永久公网 URL。
  • 更换头像后，新故事引用新资产；历史私密回执继续显示生成当时的头像快照。
  • “删除自定义头像”需二次确认：删除后所有档案与历史回执改用预设头像，相关签名立即失效，对象文件在 24 小时内物理删除。操作不可撤销。
  • 上传失败或中断不改变原头像；处理完成前显示“图片处理中”，可取消或重试，不出现“审核中”。

7. 公开发布

7.1 发布资格

同时满足以下条件才展示可用的发布按钮：

  • 用户已登录且是故事作者；故事当前为 PRIVATE，生成状态为 completed。
  • 故事正文非空、未删除、未被平台限制公开；封面失败不阻塞发布，广场使用现有兜底封面。
  • 生成链路已产生可公开安全结果，StoryPublicSnapshot.status = READY。
  • 用户账号未被限制发布；同一故事没有进行中的发布请求。

7.2 公开安全快照

为什么需要：即使公共 DTO 不返回“今晚小事”，AI 正文仍可能写出孩子昵称、学校或当天经历。直接复用私密正文会形成隐私泄漏。

生成完成后，系统在同一异步任务尾部准备一份“公开安全快照”，不改变家长看到的私密原文：

  1. 使用固定公开称呼（默认“星星小主角”，允许发布前从 3 个中性称呼中选择）替换档案昵称。
  2. 识别并移除电话号码、精确地址、学校/班级、账号标识、医疗诊断等可识别信息；不把今晚小事原文、档案 JSON 或 prompt 写入快照。
  3. 保留故事主题、情节、适龄段和生成封面；生成公开标题、公开摘要和公开正文。
  4. 无法可靠脱敏时标记 BLOCKED，故事仍为私密；用户可“重新准备公开版本”，不进入人工队列。

7.3 发布确认层

点击发布后打开移动端 Bottom Sheet，默认不勾选，不做暗示性按钮：

  • 展示公开称呼和公开版 3—5 行预览。
  • 明确说明：“公开后，所有人可在故事广场看到故事正文、封面和你的公开昵称/头像；不会公开孩子档案头像、今晚小事原文和档案资料。”
  • 勾选：“我已查看公开版并同意发布。”主按钮“确认发布”。
  • 首次发布同时提示 AI 生成内容标识规则；之后保留链接，不重复弹长协议。

7.4 同步发布与广场展示

  • 确认后调用幂等发布接口，在单个数据库事务中写入 visibility=PUBLIC、publishedAt、公开快照版本和发布日志。
  • 成功响应后立即 Toast：“已发布到故事广场”，按钮变为“已公开”，并让广场按 publishedAt desc 可查询。
  • 不创建 PUBLIC_PENDING，不展示等待时长，不发送审核通过/驳回通知。
  • 重复点击或网络重试返回同一成功结果，不重复创建公开记录、不重复埋点。
  • 公开仅代表“可发现和可访问”；现有预览/解锁/TTS/互动规则继续生效，不因公开自动免积分或免费全文。

7.5 转为私密

  • 作者在故事详情或“我的故事”卡片选择“转为私密”，确认文案说明：广场下架、公共链接失效，已有点赞/收藏/评论数据保留。
  • 确认后同步改为 PRIVATE 并主动失效列表、详情和分享缓存；非作者访问统一返回不可见，不泄漏故事存在性。
  • 可再次发布；再次发布需重新查看公开版并确认，publishedAt 更新，用于广场排序；互动数据不重置。

8. 不设人工前置审核，但保留最小安全闭环

层级机制是否阻塞用户发布
生成阶段今晚小事先做风险拦截；生成正文/封面沿用内容安全结果。安全结果未知、超时或高风险时，不准备公开快照。是；保持私密，可重试。不是人工审核。
发布阶段校验作者、完成状态、公开快照 READY、账号权限与幂等键；通过即同步公开。正常故事无等待。
传播阶段卡片与详情显著标注“AI 生成”；公开 DTO 白名单；儿童头像及私密资料永不传播。否。
公开之后公共详情“··· → 举报”，原因含儿童隐私、色情暴力、违法不良、侵权、其他；同一用户同一故事限一次有效举报。否。举报不自动定罪。
紧急处置复用现有运营后台增加“一键下架”，写入操作人、原因、时间；下架后禁止作者自行再发布，可申诉。本期不建设复杂审核队列。只影响异常内容。

举报必须进入一个明确的运营通知渠道并可追踪。上线前至少指定 1 名值班责任人和严重隐私/违法内容的处置时限；这是公共内容运营责任，不是用户发布前的审核流程。

降级原则：公开快照服务或发布安全校验不可用时，私密创作仍可继续，但隐藏/禁用发布按钮并提示“暂时无法公开，请稍后再试”；不得绕过校验直接公开。

10.2 一致性与幂等

  • 发布、撤回和平台下架必须事务化；广场列表不得先出现、详情后不可读。
  • 发布幂等键至少在用户 + storyId 维度唯一；重复请求返回当前最终状态。
  • 公开快照不可从客户端提交；客户端只选择公开称呼，正文由服务端生成和保存。
  • 历史 PUBLIC 故事按 v1.2.1 迁移事实继续公开；若没有公开安全快照，不展示第二期新增的孩子定制信息，也不得反向拼接私密快照。

场景界面状态 / 文案数据行为
头像处理中圆形进度 + “图片处理中”；保留原头像。失败不覆盖旧 avatarAssetId。
公开版准备中发布按钮禁用：“正在准备可公开版本”。私密故事正常可读。
检测到隐私细节“这个故事包含不适合公开的个人信息，暂时只能私密保存。”操作：“重新准备公开版本”。保持 PRIVATE，不产生发布记录。
发布成功Toast：“已发布到故事广场”；提供“去广场看看”。PUBLIC，写 publishedAt。
发布网络超时先查询当前状态；已 PUBLIC 则显示成功，否则可重试。幂等，不重复发布。
撤回成功Toast：“已转为私密，仅你可见”。公共列表/详情缓存失效。
公开链接已撤回/下架统一空态：“这个故事暂时无法查看”，不透露私密或下架原因。公共接口按既定安全策略返回 404/不可见。
举报重复/限频重复：“你已经反馈过了”；限频：“提交太频繁，请稍后再试”。不重复计数。

13. 非功能、隐私与安全要求

  • 最小必要：自定义头像完全可选；拒绝上传或撤回同意不影响预设头像和故事创作。
  • 最小权限：对象存储默认私有；运营后台默认看不到孩子头像与私密正文；管理员访问需独立授权和审计日志。
  • 传输与存储：HTTPS；对象存储服务端加密；临时上传凭证最短有效；限制上传频率和用户存储配额。
  • 缓存：私有头像响应不得进入公共 CDN 缓存；公开转私密和平台下架要主动 purge。
  • AI 标识：公开卡片和详情展示可感知的“AI 生成”标签；生成图片/文本如提供下载、复制或导出，需同步满足显式/隐式标识要求。
  • 日志：不记录自定义素材、孩子昵称、今晚小事原文、公开快照正文、签名 URL、对象 key 或供应商密钥。
  • 可用性：头像或公开快照子系统故障不能阻断私密故事创建、生成、阅读和 TTS。
  • 协议：上线前更新隐私政策、儿童个人信息规则、用户协议及 AI 生成内容标识说明；本 PRD 是产品约束，不替代正式法律意见。

14. 验收标准

14.1 自定义头像

  • 人物、插画、宠物、风景等合法 JPG/PNG/WebP 均可上传，不以“未检测到人脸”拒绝。
  • 伪造扩展名、超大像素、动图、损坏文件被服务端拒绝；失败时旧头像不变。
  • 输出统一为 512×512，EXIF/GPS/原文件名不可从成品恢复。
  • 跨账号无法读取或删除头像；公共接口与页面源数据搜索不到对象 key 和签名 URL。
  • 删除后所有引用回退预设头像，24 小时内验证对象已物理删除。

14.2 公开发布

  • 新故事仍默认 PRIVATE；未看到故事前没有公开选择。
  • 普通 READY 故事确认后直接 PUBLIC 并进入广场，全流程无“审核中/通过/驳回”。
  • 公开版不含孩子自定义头像、ChildProfile、今晚小事原文、孩子真实昵称和命中的可识别信息。
  • 广场卡片与详情展示“AI 生成”；使用生成封面，不使用孩子头像。
  • 重复发布请求幂等；撤回后非作者列表、详情、互动、解锁、分享链路全部不可访问。
  • 公开快照失败或安全结果未知时只能保持私密，不能通过修改请求绕过。

14.3 公开后处置

  • 举报入口可达、限频与去重有效；举报数据不向作者泄露举报人。
  • 运营一键下架立即让公共列表和详情失效，并保留操作日志。
  • 平台下架故事作者不能自行重新发布；申诉入口与服务协议一致。

16. 合规依据与未决项

以下为产品设计约束，正式上线仍需法务/合规确认：

  • 《个人信息保护法》：不满十四周岁未成年人信息属于敏感个人信息，处理需取得监护人同意并制定专门规则。
  • 《未成年人网络保护条例》：发现未成年人发布内容涉及私密信息时，应提示并采取停止传输等措施。
  • 《儿童个人信息网络保护规定》：强调正当必要、显著告知、监护人同意、删除权和安全存储。
  • 《人工智能生成合成内容标识办法》：公开传播 AI 生成文本和图片需按场景提供显式/隐式标识。
  • 《网络信息内容生态治理规定》：平台应设置便捷举报入口并及时受理处置。
