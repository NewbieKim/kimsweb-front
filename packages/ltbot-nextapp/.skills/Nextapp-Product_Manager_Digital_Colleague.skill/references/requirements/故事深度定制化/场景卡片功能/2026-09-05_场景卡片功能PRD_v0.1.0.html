2. 背景、问题与产品现状

事实问题设计约束
现有创作流程为 3 步，场景位于第 2 步“今晚去哪做梦”。不能为分类另开一级页面或增加创作步骤。继续留在第 2 步；不改导航、BottomNav 和路由。
旧交互是横向图片卡，新交互是纵向文字卡。旧版氛围感强但场景增多后难找；新版易扫读但失去想象刺激，页面会变得很长。组合两者：大类纵向提供结构，小场景横向保留氛围。
当前只有海底泡泡城、外婆的魔法菜园、云朵面包房、恐龙快递站 4 张卡。数量不足以覆盖孩子兴趣，且四者缺少清晰关系。保留四张既有卡的 id 与生成配置，重新归类并扩展到 24 张。
catalog.ts 与旧 DreamPlace.tsx 各有一份场景定义。名称、图片、分龄规则可能漂移；运营扩卡要改两处。第三期必须收敛为服务端/前端共用的单一版本化目录。
下一步已有“成长主题”。如果按勇气、分享、情绪分类，会与成长主题重复，用户不知道两步差异。场景分类只回答“故事发生在哪里”；成长主题回答“故事想陪孩子学会什么”。

3. 对标结论

产品可借鉴不直接照搬
Epic用 Topic + Age 组织大量内容，科普、自然、幻想、日常可以并列为稳定入口。其 Topic 数量极多，适合内容库检索，不适合睡前 10—30 秒的创作选择。
Khan Academy Kids同时覆盖虚构、非虚构、创造力和社会情感，并按 2—8 岁适配内容。本产品不是课程库，不把“数学、阅读”等学科直接搬成创作大类。
Storyberries年龄、类型、兴趣、讨论话题是不同维度；说明“场景”和“成长主题”应分开。不在一个页面同时展示四套筛选器，避免家长睡前配置疲劳。
取舍：首版只暴露一套“世界类型”分类；年龄适配由已选档案自动完成，不再让家长额外筛年龄。

4. 用户与场景定义

核心场景

晚上 21:10，4 岁孩子的妈妈已经完成档案选择，希望 10—20 秒内找到孩子今晚感兴趣的故事世界。孩子在旁边会看图片、指着卡片说“我要这个”。

完成标准

妈妈能理解四个大类，孩子能依靠图片识别小场景；选中后明确知道“接下来会发生什么”，返回上一步再回来时选择仍被保留。

4.1 核心任务

进入第 2 步 → 纵向扫读大类 → 在目标大类横滑 → 点击小场景 → 阅读分龄说明 → 下一步：成长主题

4.2 体验原则

  • 先看图产生兴趣，再看一句话确认，不要求家长阅读长说明。
  • 大类是浏览结构，不是额外必选项；点击小场景即完成全局唯一选择。
  • 选场景不改变成长主题、今晚小事和孩子档案。
  • 所有场景适配 0—8 岁，差异由分龄配置解决，不给孩子显示“不可用”。

5. 本期范围

本期做本期不做
四类分类；24 张小场景；分类纵向、小场景横滑；图片卡和选择详情；移动/桌面适配；分龄文案；单一目录；生成快照；加载/空/错/图片失败；埋点与灰度。新增创作步骤；大类多选；场景搜索；收藏/最近使用；每日推荐；用户自建场景；运营 CMS；按地区/节日动态分类；改造成长主题；改动一期、二期文档与原型。

P0 分类、选择、生成数据一致性与 24 张内容；P1 桌面箭头、曝光埋点和异常状态。所有内容必须在本期一起验收，不能只完成 UI 外壳。

6. 四大类与 24 个小场景

分类命名面向家长可理解、孩子可感知，并保持“世界类型”这一单一维度。

✨ 奇幻想象

进入现实中不存在、但规则温柔清楚的梦境世界。视觉方向：紫蓝夜空、发光建筑、漂浮物。

  1. 云朵面包房：坐上云车，把一枚热乎乎的月亮面包送到窗边。保留
  2. 月亮邮局：替月亮寄出一封写给星星的晚安信。
  3. 星光森林：跟着会唱歌的萤火虫，找回迷路的小星星。
  4. 玩具王国：在玩具都醒来的夜晚，完成一场温柔巡游。
  5. 糖果浮岛：乘棉花糖热气球，把彩虹果实送回岛上。
  6. 恐龙快递站：骑着温顺小翼龙，把晚安包裹送到山谷尽头。保留

🌿 自然探索

走进海洋、森林、极地与四季，重点是观察生命和环境。视觉方向：深海蓝、草木绿、冰雪青。

  1. 海底泡泡城：和章鱼公交一起，去送一封发光的信。保留
  2. 雨林树屋：沿着藤蔓电梯拜访住在树冠上的动物邻居。
  3. 极地星光站：陪小企鹅记录一场慢慢展开的极光。
  4. 昆虫旅馆：帮助瓢虫管家为夜归的小客人准备房间。
  5. 四季花谷：穿过春夏秋冬四扇门，收集不同颜色的花香。
  6. 火山温泉谷：认识温暖岩石和蒸汽，不出现喷发追逐或危险靠近。

🔭 科学发现

把真实科学概念变成可参与的小任务，知识点服务于故事，不写成课堂。视觉方向：靛蓝星空、实验室青、机械橙。

  1. 太空观测站：和机器人助手为一颗打哈欠的小行星画轨道。
  2. 天气工厂：把云、风和小雨滴装进正确的天气盒子。
  3. 机器人实验室：教小机器人分辨轻重、远近和不同声音。
  4. 身体小宇宙：乘迷你飞船认识心跳、呼吸和身体小卫士。
  5. 交通发明城：为不同道路选择轮子、船帆和安全路线。
  6. 恐龙考古营：从脚印和化石线索，拼出一位温和远古朋友。

🏠 温暖日常

把熟悉的家庭和社区生活轻轻童话化，让孩子更容易代入。视觉方向：奶油米、烛光橙、木质棕。

  1. 外婆的魔法菜园：和会说话的豆荚，一起种下发光的晚安种子。保留
  2. 晚安图书馆：帮书页里的小角色找到各自的故事房间。
  3. 小小厨房：和家人准备一碗会冒星星的暖汤。
  4. 幼儿园夜游：在安静教室里替玩具完成睡前点名。
  5. 社区便利店：帮夜班小动物把需要的物品送到正确货架。
  6. 家庭露营地：搭好帐篷、听虫鸣，在熟悉陪伴中看星星。

7. 页面与交互规则

7.1 页面结构

创作页既有头部（第 2/3 步） └─ 白色主面板“今晚去哪里做梦？” ├─ 大类 1：标题 + 一句话 │ ├─ 横向图片卡轨道（6 张） │ └─ 当前选中场景详情（仅选中时） ├─ 大类 2：同上 ├─ 大类 3：同上 └─ 大类 4：同上 固定底部：返回上一步 ｜ 下一步：成长主题

7.2 大类

  • 四个大类按“奇幻想象 → 自然探索 → 科学发现 → 温暖日常”固定纵向排列，不做标签页、折叠或横滑。
  • 标题包含图标、名称和一句价值说明；大类本身不可选，避免多一层状态。
  • 分类之间用 24—32px 间距和轻分割线区分，不套四个厚重大卡片，控制页面长度。

7.3 小场景横滑

  • 移动端卡宽约容器的 64%—72%，首屏显示 1 张完整卡 + 下一张露头 24px 以上，提示可以横滑；桌面端显示 3—4 张。
  • 轨道启用触摸惯性与 scroll-snap；桌面显示左右箭头，每次滚动约 1.5 张卡。卡片不自动轮播。
  • 卡片比例 3:4，整张为背景图；底部 40% 使用深色渐变遮罩，显示场景名和不超过 24 字的一句话。
  • 选中态为 2px 品牌色描边、右上角勾选和轻微上浮；非选中卡不降低到难辨识的透明度。
  • 点击新卡会取消全页面原选择并写入当前场景；横向拖动不触发误选。

7.4 选中详情与默认值

  • 首次进入不默认选中，底部主按钮禁用并显示“请选择一个梦境场景”；确保最终写入的是用户主动选择。
  • 选中后，在该分类轨道下展示详情：场景名、简述、当前孩子年龄对应的 1 条分龄提示。其他分类不保留空详情占位。
  • 从下一步返回时恢复选择、横向位置和纵向位置；从“用同一档案再讲一个”进入时不自动复用上次场景。
  • 主按钮变为“下一步：成长主题”，点击后沿用现有第 3 步，不生成故事、不扣积分。

7.5 响应式与可访问

  • 375px 宽度必须无页面横向溢出；只有分类内部轨道可以横向滚动。
  • 卡片是原生 button，提供 aria-pressed；轨道提供分类名称，箭头有“查看更多××场景”标签。
  • 键盘左右键切换同分类相邻卡，上下 Tab 在分类间移动；系统减少动态效果时取消平滑滚动和上浮动画。

8. 状态与异常

状态规则文案 / 降级
初始未选择四类正常展示，主按钮禁用。“选一个今晚想去的地方吧”
已选择全局唯一选中，详情紧跟所属横轨。“已选择：海底泡泡城”
加载中每类先显示 2 张固定比例骨架；大类标题不闪动。不展示全屏 Loader。
目录加载失败如果目录随包发布则不存在网络失败；若远端化，保留上次成功缓存。“场景暂时走丢了，重新加载”
单张图片失败不隐藏卡片，使用分类渐变 + emoji；仍可选择。不打断用户，不弹 Toast。
某分类为空生产配置禁止；灰度异常时隐藏该分类，不显示空轨道。日志上报 category_empty。
已选场景下线用户返回页面时取消选择并解释；历史故事继续读快照。“这个场景暂时休息了，请重新选一个。”
快速连点最后一次点击为准；点击后不发网络请求。下一步提交时仅传 sceneId。
图片弱网首个可视分类前 2 张优先，其余懒加载；渐变占位先显示。文字与选择能力先可用。

9. 场景内容生产规范

字段规则
场景名4—8 个中文字符优先，具体可画面化；不使用“勇气、分享”等成长主题词做名称。
一句话12—28 字，结构建议“和谁 + 做什么温和任务”；不承诺教育或睡眠效果。
封面3:4，主体集中在中上部，底部为文字留暗部；不含文字、水印、知名 IP、恐怖元素或危险动作。
分龄设定0—2 岁强调感官和重复；2—4 岁单线小任务；4—6 岁轻想象/观察；6—8 岁加入协作和简单推理。
故事骨架每年龄段各一份；必须有平静收束，冲突不升级，角色数遵循现有上限。
科普规则每篇最多 1—2 个可验证知识点，用情节呈现；不得编造为事实，不能写成知识问答堆砌。
安全为每张场景配置 safetyGuideline；火山、身体、恐龙、太空等场景明确避免危险模仿、医疗结论和惊吓追逐。
内容验收不是“卡片有图就算完成”：每张新场景必须同时交付封面、一句话、世界观、情绪曲线、安全规则，以及 4 个年龄段的 setting 与 storySkeleton。

10. 数据与生成契约

SceneCategory id, name, icon, description, sortOrder, status SceneCard id, categoryId, name, emoji, coverImage, briefDescription, sortOrder, status, catalogVersion, worldView, emotionalArc, safetyGuideline, settings{0-2,2-4,4-6,6-8}, skeletons{0-2,2-4,4-6,6-8} StoryCustomization.dreamWorldSnapshot sceneId, categoryId, catalogVersion, name, briefDescription, ageSetting, ageSkeleton, worldView, emotionalArc, safetyGuideline

10.1 单一来源

  • 新建一个版本化场景目录作为唯一来源；前端渲染和服务端校验均从这里导入。
  • 删除 DreamPlace.tsx 内重复的完整内容常量；组件只负责交互。生产不从第三方图片 URL 热链，封面进入项目静态/CDN 资产。
  • 首版不建设数据库和运营 CMS；24 张内容随版本发布。目录加载无网络依赖，降低睡前弱网失败。

10.2 客户端与服务端

  • 客户端状态只保存 sceneId；提交 POST /api/stories 时只传 sceneId，不上传完整配置 JSON。
  • 服务端验证 sceneId 存在且 ACTIVE，再按孩子年龄读取目录配置并写入不可变快照；不信任客户端名称、图片或 prompt。
  • 分类和卡片排序仅影响 UI；历史 StoryCustomization 读取自身快照，不随改名、换图、下线而变化。
  • 保留现有 4 个 id，避免历史和开发中数据失配；新增 id 使用英文 snake_case 且发布后不复用。

11.1 首版观察目标

  • 第 2 步完成率不低于改造前 7 日基线 -2 个百分点。
  • 首次有效选择 P50 ≤ 20 秒，返回修改率和误触率可控。
  • 至少 3 个大类获得有效选择，避免新增卡片只集中在首屏一类。
  • 图片失败率 < 1%，375px 页面横向溢出率 = 0。
  • 生成成功率、平均耗时不劣于改造前基线；sceneId 校验失败率 < 0.1%。

12. 非功能与安全要求

  • 性能：首屏只 eager 加载首类前 2 张，其余 lazy；移动端单图建议 ≤ 120KB，提供 WebP/AVIF 和尺寸集。
  • 稳定：分类目录与应用同版本发布；图片失败不影响选择，目录解析失败回退现有 4 张安全场景。
  • 移动端：375px、390px、430px 和桌面 1280px 验收；底部按钮考虑 BottomNav 和安全区。
  • 内容安全：全部为平台维护内容，不开放用户输入；新增科普事实需内容复核，禁止医疗诊断、危险模仿和高刺激叙事。
  • 可访问：对比度、键盘、焦点、aria-pressed、减少动态效果均通过。
  • 隐私：埋点只记录年龄段与目录 id，不记录孩子昵称、今晚小事或档案内容。

13. 验收标准

13.1 结构与交互

  • 第 2 步按固定顺序纵向展示 4 个大类，每类横向展示 6 张带背景图的小场景。
  • 移动端首屏能看到下一张卡露头；手势、箭头和键盘均可移动；页面本身无横向溢出。
  • 全页面只能选一个场景；换类选择时旧卡立即取消；选中详情出现在正确分类下。
  • 未选时下一步不可用；选择后可进入既有成长主题页，返回仍恢复场景和滚动位置。

13.2 内容与数据

  • 24 张卡均具备完整字段与 4 年龄段配置；现有 4 个 id 不变。
  • 前端组件与服务端不存在两份不同场景目录；客户端篡改名称/config 不影响服务端快照。
  • 历史故事不受卡片改名、换图、分类移动和下线影响。
  • 科普类样例通过事实与适龄性复核；危险/医疗/惊吓边界都有 safetyGuideline。

13.3 异常

  • 单图失败显示渐变占位并仍可选择；目录异常可回退既有 4 张。
  • 已选卡下线后要求重选，不静默替换；连续点击只提交最后 sceneId。
  • 埋点与日志不含孩子私密字段和完整生成配置。
