注册机制调研与需求方案

围绕"注册第一道门槛"问题，完成手机号登录与微信登录的可行性调研，并按前期成本优先原则确定"手机号 + 密码登录"主方案；已吸收开发评审结论，进入 v0.5。

记录时间：2026-08-25 ｜ 记录人：Nextapp 产品经理数字员工 ｜ 状态：方案 v0.5，评审结论已确认

记录摘要

核心结论：当前无企业资质条件下，微信快捷登录无法实现（需企业认证 + 年费）；手机号登录完全可行。按前期成本优先，主方案调整为首次注册用短信验证码验证手机号并设置密码，之后日常登录用"手机号 + 密码"，短信仅在注册与忘记密码时产生成本。

✅推荐方案：保留 Clerk 作为会话与账号基础设施，用国内短信能力（如阿里云短信认证，个人开发者免企业资质）做验证码下发；登录页支持"验证码登录"和"密码登录"双 Tab，验证码登录仅作为低频兜底。

方案更新记录（v0.1 → v0.2）

决策点v0.1（原）v0.2（现，已确认）
主登录方式手机号 + 短信验证码（每次登录发短信）手机号 + 密码（注册时短信验证一次，日常零短信成本）
验证码用途登录主通道仅注册验证、忘记密码重置；登录页保留"验证码登录"作为兜底
成本目标按登录频次持续产生短信成本一次性注册 + 低频重置，前期成本最优
💡权衡说明：密码登录省成本但多一步"记住密码"；验证码登录体验顺滑但有持续成本。当前阶段产品验证期用户量小，成本优先合理；后续用户量起来、体验优化时再评估"验证码一键登录"。

推荐实现路径（供开发确认细节）

  1. 自定义注册流程：手机号验证码（国内短信）→ 校验通过 → 通过 Clerk Backend SDK 创建用户（phoneNumber: ['+86...'] + password），手机号标记为已验证。
  2. 自定义登录流程：手机号 + 密码校验通过后，通过 Clerk 建立会话，沿用现有 __session Cookie 与中间件。
  3. 不调用 Clerk 预置 <SignIn />、<SignUp />；仍可使用 useSignIn / useSignUp 等 Hook 或 Backend API 完成同一套会话机制（由开发按 SDK 现状选定并验证）。
  4. 本地 User 模型：email 改为可空，新增 phone 唯一字段；同步接口与 Webhook 兼容无 email 用户。
⚠️风险提示：Clerk 版本迭代较快，Backend 建用户、手机号已验证标记、自定义会话建立的准确 API 需在开发阶段用当前 SDK 实测确认；本文给出方向和关键参数，不锁定实现细节。

国内短信对接细节

选定服务：阿里云「号码认证服务 - 短信认证」（Dypnsapi）。理由：支持个人实名认证直接接入，免企业资质、免签名/模板申请，仅支持中国大陆手机号（恰好匹配本产品），发送失败不计费。

开通前置

  • 阿里云账号完成个人实名认证。
  • 在「号码认证服务」控制台开通短信认证功能。
  • 创建 RAM 用户 AccessKey（AccessKey ID / AccessKey Secret），仅授予该服务所需权限；禁止写进代码库。
  • 在控制台获取系统赠送签名（sign_name）与系统赠送验证码模板（template_code）；不支持自定义签名/模板。

接口 1：发送验证码 SendSmsVerifyCode

参数必填说明
PhoneNumber是接收手机号，如 13800138000
SignName是系统赠送签名
TemplateCode是系统赠送验证码模板
CountryCode否默认 86（中国大陆）
Interval否发送间隔（秒），建议 60，与前端倒计时一致
ValidTime否验证码有效期（分钟），建议 5
CodeType否验证码类型，使用系统生成验证码（默认）
OutId否业务流水号，建议传 phone_register_{phone} 便于对账
💡推荐使用系统生成验证码：阿里云负责生成、存储、比对与过期，业务无需自己存验证码。若传自定义 Code，则 CheckSmsVerifyCode 不负责校验，需自研存储比对，不推荐。

接口 2：核验验证码 CheckSmsVerifyCode

参数必填说明
PhoneNumber是与发送时一致
VerifyCode是用户输入的 4-6 位验证码
CountryCode是cn（注意：此处与发送接口的 86 不同，按官方示例传 cn）
CaseAuthPolicy否大小写核验策略，默认 0
OutId否与发送时保持一致

判定规则：接口请求成功 ≠ 验证码正确；必须以返回体 Model.VerifyResult 为准：PASS = 核验通过，其他值 = 失败/过期。

调研结论

1. Clerk 手机号登录能力

能力结论依据
手机号 OTP 注册/登录✅ 支持Clerk 官方支持 phone OTP（SMS 验证码），预置组件或自定义流程均可
生产环境使用⚠️ 需付费计划官方明确：SMS 认证生产环境需要付费计划，开发模式免费
国家限制⚠️ 需开启中国区SMS 受国家 allowlist 控制，默认仅美国/加拿大；需在 Dashboard 开启中国
短信送达与成本⚠️ 风险项Clerk 短信由海外供应商发送，中国大陆 +86 号码存在送达率与合规不确定性，成本按条计

2. 微信快捷登录

路径可行性前置条件
微信开放平台"网站应用"扫码登录❌ 当前不可行需企业/个体工商户认证，300 元/年，且域名备案主体需一致
公众号网页授权（H5 内微信登录）❌ 当前不可行仅"已认证服务号"支持；订阅号、未认证服务号均不支持
微信小程序❌ 当前不可行需注册小程序账号，认证/费用/年审门槛；用户已决定后置
公众号带参二维码"关注后进入"✅ 可行（非登录）个人/未认证公众号可生成带参二维码，作为引流入口，不提供用户身份
⚠️结论：无企业资质时，"微信快捷登录"没有合规实现路径；可做的只有"关注公众号后进入 H5"的引流方式，身份仍靠手机号。

3. 个人开发者短信方案

阿里云"短信认证/号码认证服务"支持个人开发者免企业资质、免签名模板申请，通过 API 直接验证手机号；适合 H5/Web/App 的注册登录与密码找回。

方案决策

方案优点缺点结论
A. Clerk 手机号 OTP（官方通道） 改动小、复用现有 Clerk 付费计划；+86 短信海外下发送达率/合规不确定；成本不可控 备选，不推荐
推荐B. 国内短信验证码 + Clerk 会话 送达率高、个人可接入、成本可控；保留现有账号/同步体系 需自定义登录页与验证接口；Clerk 用户标识需支持手机号 推荐本期实施
C. 完全自建账号体系（弃用 Clerk） 完全自主可控 重构成本高，涉及全部 API/中间件/同步/Webhook 不推荐

业务形态：登录方式仅"手机号 + 密码"；注册与忘记密码时使用短信验证码；不做邮箱登录/邮箱绑定/存量用户合并（存量基本为 0）。

需求与交互流程

注册流程（首次）

  1. 输入 11 位手机号 → 点击"获取验证码" → 60 秒倒计时。
  2. 输入 6 位验证码，系统校验通过后进入设置密码页。
  3. 设置密码（8-20 位，字母 + 数字组合），可勾选"显示密码"。
  4. 点击"注册并登录"，自动创建账号并赠送新人积分（100 积分）。

登录流程（日常）

  1. 默认 Tab：密码登录。输入手机号 + 密码 → 点击"登录"。
  2. 忘记密码：点击"忘记密码" → 短信验证码验证手机号 → 重置密码。
  3. 登录成功后回到来源页面。

登录/注册页（合并为一页）

  1. 默认 Tab：密码登录（手机号 + 密码 + 忘记密码）。
  2. 注册入口：未注册用户从"立即注册"进入注册流程（短信验证 + 设密码）。
  3. 协议勾选：首次注册需同意《用户协议》与《隐私政策》，默认不勾选。

关键文案

  • 标题："手机号登录"；副标题："新用户注册后首次登录即送 100 积分"。
  • 按钮："登录 / 获取验证码 / 注册并登录"。
  • 协议勾选：首次注册需同意《用户协议》与《隐私政策》勾选框，默认不勾选。

状态设计

⏳加载态

发送验证码、登录校验中按钮禁用并显示 loading；发送成功后按钮进入 60 秒倒计时

⚠️错误态

手机号格式错误、密码错误（提示剩余次数）、验证码错误、发送频繁、网络异常均有独立提示

✅成功态

新用户：提示"注册成功，已赠送 100 积分"；老用户：直接进入来源页

边界与异常场景

  1. 短信防刷与成本控制：同一手机号 60 秒只能发送一次；单日发送上限（如 5 次）；验证码错误 5 次后失效需重发；IP/设备维度限流。密码登录不发短信，从源头控制成本。
  2. 验证码时效：验证码有效期 5 分钟；过期后重新获取；后端校验一次性使用。
  3. 号码注销/换绑：个人中心支持换绑手机号，需短信验证新旧号码；账号唯一性按手机号。
  4. 存量邮箱用户：不做迁移（存量基本为 0）；如需找回历史邮箱账号，另行人工处理。
  5. 游客体验：未登录用户浏览故事/音乐不受影响；仅在生成/收藏/评论/关注等操作时触发登录，并登录后回到原动作。
  6. 密码安全：密码错误连续 10 次锁定 15 分钟（自研方案，v0.5 评审确认）；锁定期间可走找回密码或客服逃生；重置密码后旧会话需重新登录。
  7. 短信通道故障：接口返回降级提示"稍后再试"，并提供"密码登录"与"邮箱登录"逃生通道。
  8. 隐私合规：隐私政策中明确手机号用途（仅用于身份验证），不得用于营销短信；提供账号注销入口。
  9. 儿童账号：注册主体为家长手机号，产品内不收集儿童手机号；生成故事所需儿童信息仅存于故事内容。

合规与成本

  • 短信验证码服务（阿里云短信认证类）个人可接入，成本按条计（预计 0.03-0.05 元/条量级，以官方为准），需在方案确认后实测报价。
  • 成本模型（主方案）：短信只在"注册 + 忘记密码"触发，日常登录零短信成本；假设单用户注册 1 条、年度重置 1-2 条，成本约为每次 0.03-0.05 元。
  • 隐私政策需更新：手机号收集目的、存储期限、第三方短信服务商披露。
  • 避免垃圾短信：验证码短信不加营销内容，发送频率受限。
