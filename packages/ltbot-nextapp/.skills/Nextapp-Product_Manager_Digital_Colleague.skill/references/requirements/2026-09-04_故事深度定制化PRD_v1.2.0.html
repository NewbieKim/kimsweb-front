1. 技术评审结论（v1.1.0 → v1.2.0）

评审意见产品结论
v1.1 与旧正文有冲突采纳。v1.2 是唯一开发契约；v1.0/v1.1 仅保留历史，不得作为实现依据。
一期应先做私密闭环采纳。第一期只做档案、今晚小事、独立快照、私密回执/详情/筛选，以及私密故事所需访问控制。
公开、审核、奖励依赖未具备采纳。移至第二期独立里程碑；不在第一期创建公开入口、审核队列或积分奖励。
真实照片缺存储/审核方案采纳。第一期使用预设头像，不上传儿童真人照片；真人照片在第二期随对象存储、审核、EXIF 清理与生命周期方案一并评审。
extData 读改写风险采纳。定制快照使用独立一对一 StoryCustomization 模型，不再写入 extData。
历史故事事实为公开确认。迁移时所有历史故事映射为 PUBLIC，维持当前线上可见行为，不做下架或批量私密化。
阻塞前置：现有故事广场/列表默认读取全部故事，详情、更新、删除和异步生成也缺少完整鉴权。第一期必须把统一访问策略和所有权校验补齐，否则新故事标记“私密”没有实际意义。

2. 第一期范围

做不做
孩子档案（昵称、年龄段、角色、性格、伙伴、预设头像）；今晚小事 ≤80 字；口味/语气各 1 项；不可变快照；新故事默认私密；专属回执、详情摘要、按孩子筛选；统一访问控制；隐私日志治理、埋点、灰度。真人照片上传；公开申请、内容审核、公开积分奖励；宠物、打卡、场景库、主题日历、TTS 扩容、图生图。全部放在后续独立里程碑。

目标：家长第二次创作不再重复填写，故事清楚回显“给谁讲、今晚发生什么”；没有任何未授权用户能读取新私密故事。

3. 第一期主流程

我的 → 孩子档案（新建 / 编辑 / 删除） 创作首屏 → 今晚讲给谁听 → 选择档案（无档案：快速建档后返回） 梦境世界 → 成长主题 → 今晚小事（可跳过）→ 高级项：口味 1 项、语气 1 项 生成 → 新故事强制 PRIVATE → 正在为 [昵称] 编织故事 → 专属回执 → 私密详情 / 用同一档案再讲一个

切换档案时，如当前主角已修改，弹确认。确认后只覆盖昵称、年龄、角色、性格、伙伴和预设头像；梦境、主题、今晚小事、口味、语气保留。第一期不存在公开选择或公开奖励入口。

4. 功能规格

4.1 孩子档案

字段规则
预设头像第一期仅可选预设头像；不提供真人照片上传。
昵称1-12 字，必填，过滤联系方式和不当内容。
年龄、角色、性格年龄必填；性格 1-3 项；复用现有主角选项。
伙伴预设伙伴或 1-12 字自定义名；第一期仍为文本/emoji。
数量、删除不设业务数量上限。删除二次确认并软删除；已生成故事由快照保证可读，不可再新建引用。

4.2 今晚小事、口味、语气

今晚小事可跳过；意图为今天发生的事、今晚想解决的事、最近喜欢的东西，输入 1-80 字。口味最多 1 项、语气最多 1 项，默认收起。高风险素材不进入模型，不做心理诊断或医疗承诺。

4.3 专属回执与详情

生成中显示“正在为 [昵称] 编织故事”。完成回执采用既定 purple/beige 夜空视觉，展示“给 [昵称] 的第 N 个故事”、预设头像、伙伴、今晚小事摘要、主题、口味、语气；无值字段不展示。详情页可展开摘要，提供“用同一档案再讲一个”；我的故事支持按档案筛选。

4.4 第 N 个故事计数

仅计算第一期之后、关联同一 ChildProfile 的故事。创建 Story 与 StoryCustomization 时在事务内对 ChildProfile 的 sequenceCounter 原子递增，并写入 snapshot.sequenceNumber。生成失败、删除故事均不回收序号，避免并发重复与历史重排。

5. 访问策略与隐私日志

主体历史 PUBLIC新 PRIVATE
匿名/非作者可读取公开 DTO、进入广场；不可读取私有快照字段。404 或 403（统一按安全策略实现）；不得从列表、详情、互动、解锁接口获知内容。
作者可读取本人故事。可读取、更新、删除、生成相关资源。
管理员/审核服务仅在独立受控接口按职责访问。第一期无公开审核业务，不开放广场审核回调。

访问策略必须覆盖故事列表、广场、详情、更新、删除、互动、解锁和异步生成接口。异步生成从数据库读取已保存的 StoryCustomization，不信任客户端 formData/customPrompt。日志只保留 storyId、阶段、耗时、错误码；移除完整 prompt、DeepSeek 配置与 process.env 输出。

6. 数据与接口契约

ChildProfile: id, userId, avatarId, nickname, ageGroup, role, traitsJson, partnerJson, sequenceCounter, createdAt, updatedAt, deletedAt Story: childProfileId(nullable), visibility(PUBLIC/PRIVATE), createdAt ... StoryCustomization (1:1 Story): storyId(unique), schemaVersion, sequenceNumber, childSnapshotJson, dreamWorldSnapshotJson, growthTheme, tonightMaterialIntent, tonightMaterialText, flavorTag, storyTone, createdAt
  • 迁移采用两步：先新增可空 visibility；把已有故事全部回填 PUBLIC；最后对新建记录默认 PRIVATE。这样历史故事按当前事实保持公开。
  • StoryCustomization 不进入 extData；extData 继续只承载 generationStatus、generationError、ttsScript 等既有生成字段。
  • 新增 GET/POST /api/child-profiles、PATCH/DELETE /api/child-profiles/:id；POST /api/stories 必须校验 childProfileId 属于 auth() 用户；生成接口只接 storyId 并从数据库读取快照。
  • 公开 DTO 不返回完整 customization、今晚小事原文或未来照片对象 key。

7. 边界、验收与灰度

场景规则
无档案快速建档；禁止以“小宝贝”默认值静默生成。
档案删除/恢复软删除、二次确认；历史故事可读；恢复后才能再次选择。
高风险今晚小事阻止进入模型，提示改写；日志和埋点不留原文。
生成失败不增加可见故事计数，不暴露部分正文；保留表单输入供重试。
并发创建以事务分配 sequenceNumber，保证同一档案不重复。
历史故事迁移为 PUBLIC，保持线上现状；无快照则不展示专属回执。
  • 跨账号读取/更新/删除档案和 PRIVATE 故事均被拒绝。
  • 改/删档案不改变历史 StoryCustomization。
  • 完成页至少回显 5 个非空定制元素；第二次创作无需重填核心档案字段。
  • 新私密故事不出现在广场、公共列表或任何非作者接口。
  • 生成成功率不低于改造前 7 天基线；白名单灰度观察创建成功率、私密越权、生成失败和日志脱敏。

8. 后续独立里程碑

里程碑进入条件范围
第二期：真人照片与公开发布对象存储供应商、真实 MIME/尺寸校验、EXIF 清理、照片生命周期、审核服务/回调验签、人工下架方案均确认；第一期访问策略回归通过。真人照片、PUBLIC_PENDING、公开授权、审核、广场 DTO 脱敏、公开转私密。
第二期：公开奖励公开审核稳定后独立评审；积分模型支持业务幂等键。5 积分/审核通过/用户自然日一次/故事唯一奖励/迟到回调防护。
第三期：陪伴资产档案复用和回访有真实基线。宠物、故事墙、轻打卡、里程碑、绘本导出按数据排序。
