PRD · 版本 1.0.0

手机号 + 密码登录注册

替换 Clerk 预置登录/注册体验，保留 Clerk 账号与会话体系；以国内短信验证码完成注册与找回密码，以手机号 + 密码完成日常登录。

需求方：产品 ｜ 评审：全栈开发数字员工（v0.5 结论已吸收） ｜ 关联方案：注册机制调研与需求方案 v0.5 ｜ 关联原型：登录/注册原型

一、产品概述

背景：上线复盘发现"注册是第一道门槛"——邮箱登录使用场景低，用户注册即流失。当前无企业资质，微信快捷登录不可行，需要低门槛、低成本的注册登录方案。

一句话目标：让家长用"手机号 + 密码"在 1 分钟内完成注册并生成第一个故事，同时不破坏现有账号/积分/故事数据体系。

用户价值

手机号人人都有，验证码注册低于邮箱门槛；首次注册送 100 积分，可直接体验生成故事

成本价值

短信只用于注册与找回密码，日常登录零短信成本；不依赖 Clerk 付费短信计划

工程价值

保留 Clerk 会话/同步/Webhook，改造面可控；为后续微信登录预留账号扩展空间

二、目标与成功指标

指标口径目标
注册完成率进入注册页 → 完成注册并登录≥ 70%（首版基线，上线后统计）
首单转化注册后 24 小时内生成至少 1 个故事≥ 50%（首版基线）
短信成本注册 + 找回密码短信单用户首年 ≤ 3 条；发送失败不计费
登录找回率忘记密码用户成功重置比例≥ 90%（抽样）

三、范围与边界

本期做

  • 自定义登录页、注册页、忘记密码页（替换 Clerk 预置组件与路由）。
  • 阿里云短信认证：发送验证码、核验验证码。
  • 手机号 + 密码登录；注册强制设密码；忘记密码重置。
  • 保留 Clerk 账号/会话/同步/Webhook；本地 User 增加 phone 字段。
  • 游客可浏览，写操作要求登录；密码错误 10 次锁定 15 分钟（自研）。
  • 新用户注册赠送 100 积分。

本期不做

  • 微信登录/小程序登录（需企业资质，列入后续路线图）。
  • 邮箱登录、存量用户迁移与账号合并（存量基本为 0）。
  • 验证码一键登录（成本高，用户量起来后评估）。
  • 手机号换绑（个人中心二期）。

五、功能流程

F1 注册（手机号 → 验证码 → 设密码）

登录页 → 点击"立即注册"
  → 输入手机号（11 位，1[3-9] 开头）→ 点击"获取验证码"
    → 校验通过：60s 倒计时，阿里云下发验证码（有效期 5 分钟）
  → 输入 6 位验证码 + 勾选协议 → 点击"下一步"
    → 校验通过：进入设置密码页（8-20 位，字母+数字）
  → 确认密码一致 → 点击"注册并登录"
    → 创建 Clerk 用户（phone + password）→ 建立会话
    → 本地 User 同步 + 赠送 100 积分
  → 成功页：倒计时 5s 自动进入首页（可点"进入首页"跳过）

F2 登录（手机号 + 密码）

登录页（默认密码 Tab）
  → 输入手机号 + 密码 → 点击"登录"
  → 成功：回到来源页面（无来源则首页）
  → 失败：提示剩余次数；连续 10 次错误 → 锁定 15 分钟
  → 锁定：引导"忘记密码"或"联系客服"

F3 忘记密码

登录页 → "忘记密码"
  → 输入手机号 → 获取验证码 → 输入验证码
  → 设置新密码（校验同注册）→ 重置成功
  → 旧会话失效，返回登录页使用新密码登录
  → 逃生通道：短信不可达时，提供"联系客服"入口（管理员人工重置）

F4 游客模式与登录拦截

游客可访问：首页、故事列表、故事详情（未解锁预览）、音乐广场
触发登录的操作：生成故事/音乐、点赞、收藏、评论、关注、积分消费/解锁
  → 打开登录弹层/跳转登录页 → 登录成功 → 回到原操作（不丢上下文）

6.2 输入校验

字段规则错误提示

6.3 状态设计

加载态

发送验证码、提交登录/注册时按钮禁用 + loading；验证码按钮 60s 倒计时

错误态

字段级错误、验证码错误、密码错误剩余次数、锁定提示、短信通道故障提示均独立

成功态

注册成功页显示"5 秒后自动登录并进入首页"倒计时；登录成功回来源页

空态/兜底

短信不可达 → "联系客服"入口；验证码登录兜底本期不做

七、接口契约

💡统一响应格式复用 src/lib/response.ts（successResponse / errorResponse / badRequestResponse / unauthorizedResponse 等）；前端请求统一走 src/lib/request.ts。

7.1 POST /api/auth/send-code

用途：发送短信验证码（注册 / 忘记密码）。

// Request
{ "phone": "13800138000", "scene": "register" | "forgot" }

// Response 200
{ "success": true, "code": 200, "message": "验证码已发送", "data": { "expireInSeconds": 300 } }

// 错误
400 参数错误（手机号格式错误）
429 发送过于频繁（60 秒内重复 / 单日超过 5 条）
500 短信通道故障（前端提示稍后重试，并提供客服入口）

后端要点：调阿里云 SendSmsVerifyCode（interval=60，validTime=5，countryCode=86）；防刷：同号 60s、单日 5 条、IP/设备限流。

7.2 POST /api/auth/verify-code

用途：核验验证码（注册下一步 / 忘记密码下一步）。

// Request
{ "phone": "13800138000", "code": "123456", "scene": "register" | "forgot" }

// Response 200
{ "success": true, "code": 200, "message": "验证码核验成功", "data": { "verified": true, "token": "verify_xxx" } }

// 错误
400 验证码错误或已过期
429 尝试次数过多（错误 5 次后失效）

后端要点：调阿里云 CheckSmsVerifyCode，以 Model.VerifyResult === 'PASS' 判定；核验通过后返回短期凭证（如 5 分钟有效的 verifyToken），供注册/重置接口绑定手机号使用，防止跨场景伪造。

7.3 POST /api/auth/register

用途：完成注册（验证码已核验 + 设置密码）。

// Request
{ "verifyToken": "verify_xxx", "phone": "13800138000", "password": "Abc12345" }

// Response 200
{ "success": true, "code": 200, "message": "注册成功",
  "data": { "user": { "id": "user_xxx", "phone": "13800138000", "name": "用户" },
            "isNewUser": true, "giftScores": 100 } }

// 错误
400 参数错误 / 手机号已注册
401 verifyToken 无效或过期

后端要点：校验 verifyToken 与手机号一致；手机号已存在则拒绝；通过 Clerk 创建用户（phone 为主标识 + password，标记已验证）；建立会话；本地 User 同步并赠送 100 积分（沿用现有 sync 逻辑）。

7.4 POST /api/auth/login

用途：手机号 + 密码登录。

// Request
{ "phone": "13800138000", "password": "Abc12345" }

// Response 200
{ "success": true, "code": 200, "message": "登录成功",
  "data": { "user": { "id": "user_xxx", "phone": "13800138000", "name": "用户" }, "isNewUser": false } }

// 错误
400 参数错误
401 手机号或密码错误（返回 remainingAttempts）
423 账号锁定（返回 lockRemainingSeconds）
404 手机号未注册（提示先去注册）

后端要点：通过 Clerk 校验手机号 + 密码并建立会话；密码错误计数自研（本地存储，见数据模型）；连续 10 次错误锁定 15 分钟；锁定期间提示引导"忘记密码 / 联系客服"。

7.5 POST /api/auth/reset-password

用途：忘记密码重置。

// Request
{ "verifyToken": "verify_xxx", "phone": "13800138000", "password": "Abc12345" }

// Response 200
{ "success": true, "code": 200, "message": "密码重置成功", "data": { "redirect": "/sign-in" } }

后端要点：校验 verifyToken 与手机号一致；通过 Clerk 更新密码；使旧会话失效；清除该手机号锁定计数。

7.6 存量接口鉴权修正（随本期一并处理）

接口现状问题本期要求
POST /api/scores/consume信任 body.userId，未校验登录态改用 auth() 取当前用户，禁止客户端传 userId；未登录返回 401
POST /api/stories 等写接口部分依赖前端传 userId统一以服务端 auth()/currentUser() 为准；客户端传入的 userId 一律忽略
互动接口（like/favorite/comment/follow）同上未登录返回 401，由前端触发登录弹层并回原动作

八、数据模型

8.1 User 表变更（Prisma）

model User {
  id        String   @id                  // Clerk userId，格式不变
  name      String
  email     String?  @unique              // 改为可空；本期不依赖
  phone     String?  @unique              // 新增：手机号主标识（E.164 或 11 位纯数字，与 Clerk 统一后定）
  avatar    String?
  age       Int?
  extData   String?
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
  // 现有关联关系保持不变
}

8.2 新增 AuthAttempt / 锁定计数（自研）

model LoginAttempt {
  id        Int      @id @default(autoincrement())
  phone     String   @unique              // 按手机号计数（未注册手机号也可计数防爆破）
  failCount Int      @default(0)
  lockedAt  DateTime?                     // 非空表示锁定中
  updatedAt DateTime @updatedAt
}

// 短信发送频控：可复用内存/Redis（无 Redis 时 SQLite 表 + 索引亦可，开发确认）
model SmsSendLog {
  id        Int      @id @default(autoincrement())
  phone     String
  scene     String                         // register | forgot
  ip        String?
  createdAt DateTime @default(now())
  @@index([phone, createdAt])
}
⚠️开发决策点：锁定计数与短信频控的存储选型（SQLite 表 vs Redis）。项目当前 SQLite 单实例，先用数据库表实现；若后续上 Redis 再迁移，接口契约不变。

九、安全与合规

  • 密钥管理：阿里云 AccessKey、Clerk Secret Key 只存服务端环境变量，禁止入库/入前端；生成文档与日志时脱敏。
  • 验证码安全：阿里云系统生成验证码，业务不存验证码明文；核验以 Model.VerifyResult 为准；核验通过发短期 verifyToken（5 分钟、单次有效、绑定手机号）。
  • 接口鉴权：所有写接口服务端校验登录态与资源归属；前端传入的 userId 一律忽略，防止越权。
  • 防爆破：密码错误计数 + 锁定；短信发送频控；验证码错误 5 次失效。
  • 隐私合规：隐私政策更新手机号收集用途；验证码短信不含营销内容；提供"联系客服"渠道与账号注销入口（注销为后续项，本期至少提供说明）。
  • 儿童保护：注册主体为家长手机号；不收集儿童手机号；儿童信息仅存在于故事内容。

十一、验收标准

  1. 新用户手机号 + 验证码 + 设密码注册成功，自动登录并收到 100 积分。
  2. 老用户手机号 + 密码登录成功，回到来源页面。
  3. 密码错误累计 10 次锁定 15 分钟，锁定期间可走找回密码或联系客服。
  4. 验证码错误/过期/发送频繁有明确提示且无法绕过。
  5. 忘记密码：短信验证通过后可重置，旧会话失效，新密码可登录。
  6. 游客可浏览首页/故事列表/详情预览/音乐广场；写操作触发登录并回原动作。
  7. 无邮箱用户可正常同步、生成故事、查看个人中心，无空白报错。
  8. 所有写接口不再信任客户端 userId，未登录返回 401。
  9. 隐私政策与协议文案已更新；阿里云 AccessKey 只存服务端。
  10. pnpm lint、pnpm build 通过；移动端（375px）与桌面端主流程手工验证通过。
