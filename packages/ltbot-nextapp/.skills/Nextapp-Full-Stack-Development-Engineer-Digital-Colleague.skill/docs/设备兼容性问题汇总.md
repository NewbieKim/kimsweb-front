# 设备兼容性问题汇总

> 状态：已完成 P0 修复，待生产发布后进行真机回归
> 更新时间：2026-09-16

## 1. 兼容目标

| 平台 | 支持范围 | 必测载体 |
| --- | --- | --- |
| iPhone / iPad | iOS 15.0+ | Safari、微信内置浏览器 |
| Android | Android 10+ | Chrome、微信内置浏览器 |
| 桌面端 | 最新两个主版本 | Chrome、Safari、Edge |

设备型号不是兼容性边界；iOS 系统版本和 WebView 内核版本才是。iPhone 的微信内置浏览器使用系统 WebKit，因此需要与 Safari 同时验证。

## 2. 已发现问题与根因

### P0：iOS 15 页面无法交互

**现象**：个人中心一直显示“加载中”；故事/音乐卡片、主题切换、主菜单均无法点击。

**根因**：线上 Next.js 16 的默认浏览器支持线为 Safari 16.4+。其 App Router 启动代码会使用 `Array.prototype.at()` 和 `Object.hasOwn()`；iOS 15.0–15.3 不提供这两个 API。脚本在 React hydration 前异常，故服务端 HTML 可见，但所有 React 事件都未接管。

**修复**：新增 `src/lib/browser-compat.ts`，在根布局 `<head>` 中同步执行最小 polyfill，确保在任意 Next 客户端脚本之前补齐 `Array.prototype.at`、`String.prototype.at`、`Object.hasOwn`。

### P0：故事卡片默认书籍封面空白

**现象**：探索页的故事卡片存在标签和文本，但封面区域是白色。

**根因**：代码引用 `/story-cover-1.jpg` 至 `/story-cover-5.jpg`，仓库的 `public/` 并没有这些文件；线上静态资源返回 404，Next 图片优化接口返回 400。原有降级界面依赖客户端 `onError`，恰好会被上述 hydration 故障一起阻断。

**修复**：

- 新增本地随包封面 `public/story-cover-default.jpg`（600×800，约 113KB）。
- 故事卡片统一使用该已验证的本地默认封面。
- 卡片底层始终输出 CSS 书籍降级层；即使图片不可用或客户端脚本没有执行，也不会留下一片空白。
- 封面使用原生 `<img>`。插画 Provider 变更域名时不会触发 `next/image` 白名单异常并影响组件渲染。

### P1：刘海屏和微信 WebView 的底部安全区

**现状**：最新代码已通过 `viewportFit: 'cover'`、`env(safe-area-inset-top/bottom)` 与 AppShell 的底部预留处理安全区；本次验证纳入回归用例，未重复改写现有实现。
