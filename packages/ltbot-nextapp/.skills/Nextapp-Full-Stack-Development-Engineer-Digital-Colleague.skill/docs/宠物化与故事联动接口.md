# 宠物化与定制故事联动接口（2026-09-18）

适用范围：`ltbot-nextapp` H5，一期。所有接口均要求登录；按 `ChildProfile.userId` 校验档案归属。旧 `CompanionGrowth`、`ChildFoodCard`、`CompanionFeedRecord`、`CompanionMilestone` 仅通过归档接口读取，新写操作使用 `ChildPet` 和 `Pet*` 表。

## 宠物目录与领养

| 接口 | 请求 / 结果 | 关键规则 |
| --- | --- | --- |
| `GET /api/pets` | 返回启用的 12 种宠物、`petKey`、名字、性格、`assetVersion`、`spriteUrl` | 服务端目录控制可领养集合；素材路径 `/habits/pets/v{assetVersion}/{petKey}.png` |
| `POST /api/child-profiles/{id}/companion` | `{ "petKey": "rabbit", "displayName": "小芽" }`；名字可省略 | 档案一宠物；并发重复领养返回冲突。新成长值 0、空库存，旧资产不迁入 |
| `GET /api/child-profiles/{id}/companion` | 宠物、成长、库存、待喂卡、今日成长和阶段 | 未领养返回 `PET_ADOPTION_REQUIRED` |
| `PATCH /api/child-profiles/{id}/companion` | `{ "displayName": "小芽", "appearanceKey": "cat" }` | 名字可改；首次成功喂养后变更物种返回 `PET_SPECIES_LOCKED`；旧接口不再写旧伙伴 |
| `GET /api/child-profiles/{id}/legacy-habit-assets` | 旧成长、旧卡、旧喂养、旧里程碑 | 只读，不向新宠物发卡或消费 |

`GET /api/child-profiles/{id}/habits` 增加 `pet` 和 `adoptionRequired`。新打卡要求已领养；旧日完成位与奖励位仍计入占用。新 `HabitCheckIn.petEra=true`，即使每日奖励名额已满、未生成 grant，也可以按新规则撤销；旧打卡默认为 `false` 且只读。新 `CheckInRewardGrant.petEra=true`，旧 grant 默认为 `false` 并拒绝选卡、喂养等新写操作。新食物图鉴只读新宠物库存，旧库存见归档。

## 定制故事

`POST /api/stories` 的定制请求增加 `includePet?: boolean`，缺省视为 `true`。仅 `mode="customized"` 使用；quick / continuation 不受影响。`includePet=true` 且未领养时返回 HTTP 409、`errorCode="PET_ADOPTION_REQUIRED"`；创作页把草稿按当前登录账户临时保存在浏览器会话，领养返回后继续。`includePet=false` 不读取宠物；定制故事创作服务也不读取或注入旧伙伴字段。

创建事务会冻结 `petKey`、宠物名、性格、`assetVersion`、当前最高阶段以及最多三条由服务端白名单生成的共同经历；客户端无法提供宠物事实。故事 `schemaVersion=3` 保存 `includePet` 与 `petSnapshotJson`。重试使用同一快照，不因改名或后续打卡变化而重写。

`POST /api/stories/generate-async` 生成正文后校验宠物名及物种；不合格补一次生成，仍不合格记失败，正文和成功计数均不落库。成功时同一事务写正文、`ChildProfile.successfulStoryCount` 和（仅带宠物时）`ChildPet.completedAdventureCount`，并写 `successOrdinal` / `petAdventureOrdinal`。重复完成只成功提交一次；后续删除故事不扣累计数或改其他编号。旧基线只包括上线时数据库仍保留且正文非空的定制故事。

`GET /api/stories/{id}` 中的 `customization` 对故事主人增加 `successOrdinal`、`includePet`、`pet`、`petAdventureOrdinal`。新故事结果与详情按快照展示宠物；关闭选项的故事不展示宠物纪念，旧故事仍可查看历史伙伴摘要。

## 发布与回退

先备份数据库并依次应用 `20260918130000_add_child_pets_and_story_success`、`20260918143000_mark_pet_era_check_ins`，确认 12 张版本化素材存在，再开放领养/打卡，最后开放定制故事宠物选项。关闭新入口时，已写宠物/故事与旧资产继续可读；不做破坏性回滚。成长阶段：`0–9 / 10–29 / 30–69 / 70–139 / 140+`，营养轨保留展示但不参与晋级。

本地回归可在已安装 Chrome 但 Playwright 专用 Chromium 尚未下载时设置 `PLAYWRIGHT_CHROMIUM_CHANNEL=chrome`，运行桌面与移动视口测试。WebKit 必须单独验证，不能以 Chrome 移动视口代替。灰度上线前还需登录态实机验收领养、喂养、创作和结果页。
