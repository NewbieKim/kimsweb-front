# ltbot-nextapp 运营现状基线

> 最后更新：2026-08-25。本文件只维护稳定的运营事实，动态过程见 `records/`。判断现状以源码 + 最近提交 + 线上实测为准。

## 产品与目标用户

- 产品名：AI 睡眠伙伴（LTBot Next.js），H5 产品。
- 线上地址：https://space.ltbot.top
- 一句话定位：面向 0-8 岁儿童家庭的 AI 个性化睡前故事与亲子陪伴工具。
- 用户：家长是付费/决策用户，孩子是体验核心；首批优先 3-6 岁孩子家长。
- 当前阶段：功能已验证、真实用户量极少、运营冷启动未闭环。
- 渠道主张：微信生态（朋友圈/社群/私域）+ 小红书内容种草；H5 先行。

## 数据与埋点现状（实测）

| 事件 | 定义 | 实际埋点 | 说明 |
| --- | --- | --- | --- |
| `story_create` | 有 | 服务端 | `/api/stories` POST 已上报 |
| `story_generate_success/failed` | 有 | 服务端 | 异步生成完成/失败已上报 |
| `tts_play` | 有 | 服务端 | `/api/tts` 已上报 |
| `page_view` | 有 | **未接入** | 前端无任何调用，看板 UV/漏斗空转 |
| `feedback_submit` | 有 | **未接入** | 尚无反馈表单触发 |

- `visitorId` 机制存在（OperationEvent 表支持、看板按 visitorId 去重），但前端未生成/透传。
- 看板指标口径：UV 按 visitorId 去重、生成成功率 = 成功 / (成功 + 失败)、漏斗 = UV → 登录 → 创作 → 生成成功 → TTS 播放。
- 缺失体验指标：TTS 完播率、重复收听率、哄睡时长、故事停留时长。

## 内容与品牌现状

- 成长主题库：4 大维度 36 个主题（健康自理/情绪社交/勇气探索/品格感恩）。
- Prompt 已具备分龄约束（0-2 / 2-4 / 4-6 / 6-8：词汇、句式、情节、字数）、禁词（突然/快/危险/别怕）、节奏 3:1、结尾渐进降能、风味标签。
- 品牌调性：温暖、专业、有爱；主题 purple / beige。
- 待沉淀：把 prompt 约束转化为可执行的"儿童友好内容标准 SOP"，含人工抽检机制。

## 渠道与增长现状

- 无正式投放；分享仅 Web Share / 复制链接，无分享海报、无渠道追踪参数、无邀请码。
- 音乐广场具备冷启动钩子潜力，但尚未承担引流功能。
- B 端异业（幼儿园/绘本馆/早教机构）、故事定制师均未启动。

## 用户与社群现状

- 无社群、无体验官体系、无 UGC 共创活动。
- 产品内互动能力已具备（评论/收藏/关注/续集），可作为社群与共创的载体。
- 无内测反馈表单入口（`feedback_submit` 未埋）。

## 风险清单

- **P0 合规**：首页"10,000+ 家庭喜爱"与家长评价为硬编码虚构内容，儿童产品叠加广告法，投放前必须整改。
- **P0 数据**：`page_view` 未埋，看板 UV/漏斗空转，运营结论不可建立在该数据上。
- **P1 定位冲突**：首页"无广告/亲子陪伴"叙事与广告解锁方案需统一，避免信任反噬。
- **P1 内容安全**：prompt 有约束但无人工抽检与审核 SOP。
- **P2 经济闭环**：积分无实际消费路径；插画未启用；支付未接入。

## 后续运营方向

- **P0 运营底座（第一优先级）**：接通前端 `page_view` 埋点与 `visitorId`；整改首页合规文案；建立运营周报模板与指标口径。
- **P1 冷启动闭环**：内测反馈闭环（体验官 + 反馈表入口）；主题日历 + 每日睡前故事推荐；分享海报 + 渠道追踪参数。
- **P2 增长与共创**：家长共学社群；UGC 共创（把"创作续集"包装成"孩子续编故事"）；B 端异业（幼儿园午睡故事定制）；故事定制师。
- **北极星候选**：每周成功生成故事的家庭数；体验指标：TTS 完播率、重复收听率、哄睡时长。

## 运营看板指标框架（2026-08-25 方向）

- 北极星：每周成功生成故事的家庭数；护栏：生成成功率、TTS 失败率、内容不适率。
- 八层框架：概览 / 转化漏斗 / 体验留存 / 内容质量 / 用户社区 / 渠道增长 / 商业化 / 稳定性。
- 核心体验指标：TTS 播放率、TTS 完播率（进度 ≥80% 或末段播放完成）、重复收听率（同故事 7 天内 ≥2 次）、平均陪伴时长、D1/D7（按家庭口径）。
- 漏斗：访问 → 登录 → 完成三步创作 → 生成成功 → 详情 → TTS → 回访。
- 数据基座缺口：`page_view` 前端埋点、`visitorId` 生成透传、创作三步事件、`tts_complete`、`share_click`、渠道参数。
- 落地批次：第一批概览+漏斗+稳定性；第二批体验留存+内容质量+反馈；第三批渠道归因+商业化。
- 详细设计见 `records/2026-08-25_运营看板指标设计.md.html`。
