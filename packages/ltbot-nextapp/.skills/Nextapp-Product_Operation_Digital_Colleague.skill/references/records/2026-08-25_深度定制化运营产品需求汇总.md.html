记录摘要

基于代码级体验走查、线上实测与场景卡片示例（V1.0，15 张）对标，运营侧发现"深度定制化"当前存在四类问题：感知弱、复用难、真实影响不足、无资产沉淀。报告共提出 10 项问题（4 高 / 5 中 / 1 低），覆盖场景卡片、成长主题、TTS 音色、个性化宠物、个性打卡及专属回显、孩子档案、今晚素材、故事口味等定制化全链路。

⚠️数据纪律说明：当前 page_view 未埋、无真实用户样本。本报告中"数据支撑"以代码级证据与可验证假设为主，用户声音为场景预演（标注待验证），目标值需在埋点上线后校准，不虚构证言。

一、背景概述

深度定制化是产品最重要的差异化卖点，但当前体验"鸡肋"：用户投入了主角、伙伴、世界、主题等多类定制输入，生成后却看不到专属结果。基于代码走查、线上实测与场景卡片示例对标，运营侧梳理出定制化在感知、复用、真实影响、资产沉淀四个维度的优化空间，形成以下需求汇总，供产品团队排期。

三、运营目标与期望

  • 定制复用率：埋点上线后 4 周内，30 天内第二次创作使用孩子档案的比例 ≥70%（基线待校准）。
  • 专属感认同：内测 N≥30 家庭，"感觉是为我家孩子写的"认同率 ≥60%。
  • 首单时长：建档后首次生成故事从约 5 分钟降至 ≤2 分钟。
  • 回访：同一主角系列故事创作率 ≥25%。
  • 体验指标：TTS 播放率 / 完播率随音色丰富提升，基线在埋点上线后建立。
💡目标为方向性承诺，验收时以埋点基线校准；短期可用"生成后 24h 回访、分享点击、定制要素使用分布"作为过程指标。

四、问题清单

OP-001

定制结果不可见：生成后无专属回显

🔴 高

问题类型：交互体验

  • 问题描述：家长填了主角、伙伴、世界、主题等 6 类信息，生成后仅正文出现名字；封面取自 5 张默认图池（storyId % 5），详情页无"主角是谁"回显，也无"给 XXX 的第 N 个故事"仪式感。
  • 影响范围：覆盖全部创作用户，直接决定"定制化"卖点是否成立，影响分享与回访。
  • 数据支撑：StoryCard.tsx 默认封面池 5 张按 storyId 轮换；详情页无主角卡；extData 无定制摘要字段。
  • 用户声音（预演待验证）："填了一堆，最后看起来和别人的故事没差别。"
  • 改进建议：A. 生成完成页新增"专属故事卡"（主角头像/昵称/伙伴/世界/主题/音色回显 + 可分享图，3-5 人日）；B. 详情页主角卡 + "给 XXX 的第 N 个故事"（2 人日）；C. 封面按主角生成插画（依赖插画链路，后置）。建议 A→B→C。
  • 预期价值：定制感知可测（分享率、24h 回访）；为"专属感"提供可视化载体。
OP-002

孩子档案缺失：每次创作重复填写

🔴 高

问题类型：功能缺失

  • 问题描述：无孩子档案模型，每次创作从默认值重新填写，无"给谁讲"入口，多娃家庭无区分。
  • 影响范围：所有老用户；降低高频使用意愿；也是系列故事、宠物、打卡的前置依赖。
  • 数据支撑：schema.prisma 无孩子档案模型；create-story 每次初始化为默认值。
  • 用户声音（预演待验证）："每天都重新填，太麻烦了。"
  • 改进建议：A. 建档 MVP（昵称/头像/年龄/性格/伙伴，1 家庭 N 孩子，创作页顶部"给谁讲"，5-8 人日）；B. 档案自动带出 + 我的故事按孩子归档（3-5 人日）；C. 多娃档案管理（远期）。
  • 预期价值：首单时长下降、复用率上升；为宠物与打卡打底座。
OP-003

存在"假定制"：头像不落库、封面固定图池、伙伴无形象

🔴 高

问题类型：内容质量

  • 问题描述：上传头像仅本地预览，保存时只存文本描述，头像不进故事；封面固定图池；伙伴只有 emoji。
  • 影响范围：制造"填了没变化"的落差，损伤信任与口碑。
  • 数据支撑：CharacterAndPartner.tsx 头像为 blob URL；GenerateStory 仅保存 characterSetting 文本；StoryCard 封面池。
  • 用户声音（预演待验证）："头像传了好像没什么用。"
  • 改进建议：A. 头像/伙伴形象入档案并进入"专属故事卡"（2-3 人日）；B. 伙伴形象库（预设插画/剪影替代纯 emoji，5-8 人日）；C. 插画链路启用后主角/伙伴进分镜。
  • 预期价值：消除"假定制"，感知差异直接可见。
OP-004

今晚素材缺失：真实生活进不了故事

🔴 高

问题类型：功能缺失

  • 问题描述：睡前故事最打动的场景是"今天发生的事"，当前仅自由主题输入，无结构化"今晚素材"入口（今天发生了什么 / 怕什么 / 想解决什么）。
  • 影响范围：0-8 岁全年龄家庭；直接影响故事贴合度与口碑；也是成长记录的数据源。
  • 数据支撑：TodaySubject.tsx 仅主题 + 自定义输入；prompt 无"今日事件"字段。
  • 用户声音（预演待验证）："能不能把今天幼儿园的事编进去？"
  • 改进建议：A. "今晚的小秘密"一句话 + 3 类快捷卡（今天发生的 / 今晚想解决的 / 最近喜欢的，3 人日）；B. 素材进 prompt 结构化字段并回显到专属故事卡；C. 敏感词过滤与隐私提示。
  • 预期价值：最强差异化叙事点；数据可沉淀为成长记录（联动 OP-010）。
OP-005

场景卡片库过小且缺分龄故事方向

🟡 中

问题类型：内容质量

  • 问题描述：当前仅 4 张卡片；已设计的场景卡片库 V1.0（15 张、6 大维度、三阶分龄方向、风味标签、0-2 岁极简模式）未落地。
  • 影响范围：内容丰富度与重复使用意愿；0-2 岁用户无适配入口。
  • 数据支撑：DreamPlace.tsx 仅 4 张；示例见 records/20260825场景卡片示例.html。
  • 用户声音（预演待验证）："世界就这几个，孩子听几天就腻了。"
  • 改进建议：A. 按示例扩展 12-15 张（沿用 settings / storySkeletons / skeletonFeatures 配置结构，开发 3-5 人日 + 内容生产）；B. 0-2 岁极简模式；C. 运营可配置化扩展。
  • 预期价值：内容新鲜度上升、重复使用上升、0-2 岁覆盖补齐。
OP-006

成长主题选择体验：36 主题扁平化 + 随机 9

🟡 中

问题类型：交互体验

  • 问题描述：常量含 4 维度 36 主题，UI 拍平后随机展示 9 个；无分类导航、无"每日推荐主题"运营位。
  • 影响范围：选择压力与随机感；主题教育价值被隐藏；缺每日推荐留存抓手。
  • 数据支撑：QUICK_GROWTH_THEME_CATEGORIES 4 维度；TodaySubject 拍平 + pickRandomThemeBatch(9)。
  • 用户声音（预演待验证）："换一批还是这些，不知道选啥。"
  • 改进建议：A. 按 4 维度分类展示（保留快捷 9 宫格，2-3 人日）；B. "今日推荐主题"运营位（后台配置主题日历）；C. 历史使用主题优先。
  • 预期价值：主题价值可感知；为主题日历留存抓手铺路。
OP-007

故事口味/语气无 UI 入口

🟡 中

问题类型：功能缺失

  • 问题描述：prompt 已支持风味标签（小百科 / 传统智慧 / 加油打气 / 搞笑放松 / 魔法满天飞）与情绪语气，创作 UI 无入口。
  • 影响范围：差异化能力被浪费；用户无法表达"今晚要轻松一点还是安静一点"。
  • 数据支撑：generate-async 的 flavorTags / emotionTone 逻辑存在；create-story 表单无对应字段。
  • 用户声音（预演待验证）："能不能选个轻松一点的？"
  • 改进建议：A. 创作第 3 步加"故事口味"多选（3-5 个高频项）与"今晚语气"单选（2-3 人日）；B. 默认值 + 高级展开降低负担；C. 埋点记录选择分布。
  • 预期价值：低开发量获得高感知差异；为故事风格 A/B 提供入口。
OP-008

TTS 音色单一

🟡 中

问题类型：功能缺失

  • 问题描述：仅温柔妈妈 / 贴心爸爸 2 个角色；配置驱动可扩展，但无运营扩展内容。
  • 影响范围：反复收听疲劳；"家庭声音"角色感弱。
  • 数据支撑：ttsVoices.ts 仅 2 个角色。
  • 用户声音（预演待验证）："想要个更萌一点的宝宝音。"
  • 改进建议：A. 扩展 6-8 个音色（萌宝 / 姐姐 / 外婆 / 爷爷等，配置表 + Azure 音色，2-4 人日）；B. 音色与宠物 / 伙伴绑定；C. 家长声音克隆列远期调研（隐私与合规慎做）。
  • 预期价值：播放率 / 完播率提升可测；增强"家庭声音"专属感。
OP-009

个性化宠物缺失

🟡 中

问题类型：功能缺失

  • 问题描述：伙伴仅 emoji；无陪伴型虚拟角色资产（形象 / 声音 / 成长）。
  • 影响范围：情感连接与长期留存载体缺失；也是 UGC / 共创的载体。
  • 数据支撑：schema 无宠物模型；伙伴仅为字符串。
  • 用户声音（预演待验证）："孩子想要一只自己的小恐龙。"
  • 改进建议：A. 伙伴升级为宠物（预设形象库 + 名字 + 音色绑定 + 专属卡展示，5-10 人日）；B. 宠物随故事宇宙成长（等级 / 口头禅 / 出场率，10+ 人日）；C. 宠物形象进插画分镜。
  • 预期价值：情感资产，驱动重复使用与分享。
OP-010

个性打卡/成长记录缺失

🟢 低

问题类型：数据/算法

  • 问题描述：无打卡、无连续记录、无"我们的故事"合集；定制内容没有沉淀为家庭资产。
  • 影响范围：长期留存与口碑；数据层面无法回答"陪伴是否持续"。
  • 数据支撑：schema 无打卡 / 系列模型；个人中心仅收藏 / 点赞。
  • 用户声音（预演待验证）："能不能记录一下我们讲了几天故事？"
  • 改进建议：A. 生成故事自动归档"给谁讲 + 日期 + 主题"，个人中心"孩子的故事墙"（5-8 人日）；B. 轻量打卡（连续天数 / 里程碑，防刷上限，3-5 人日）；C. 导出 / 分享绘本（远期）。
  • 预期价值：留存抓手 + 情感资产 + 家庭行为数据源。

六、典型案例详述

案例一：小禾妈妈（预演案例，待真实访谈替换）

用户画像：33 岁，一线城市，4 岁女儿，已连续使用 7 天。

使用场景：每晚睡前生成故事，孩子总问"我的小兔子怎么没来"。

遇到的问题：每次都要重填主角信息；生成的故事和普通故事看不出差别；头像、伙伴像摆设；无法记录连续讲了几天。

期望的改进：产品记住我家孩子；今晚发生的事能进故事；有"我们的故事墙"可以回看。

案例二：陈老师，幼儿园中班老师

使用场景：午睡前需要短故事，按习惯养成主题批量生成，并需要 0-2 岁极简安抚内容。

遇到的问题：场景卡片太少、主题随机，备课不便。

期望的改进：场景 / 主题可快速检索配置，能保存"班级常用设定"。

八、改进成功标准

  1. 功能验收：档案支持"给谁讲"；专属故事卡回显 ≥5 个定制要素；封面不再固定图池；口味 / 语气可选并进入 prompt；TTS ≥6 音色；场景卡片 ≥12；打卡可连续计数。
  2. 数据验收（埋点上线后以基线校准）：定制复用率 ≥40%（4 周）；生成后 24h 回访率提升 ≥10pp；TTS 播放率提升 ≥10pp。
  3. 用户反馈验收：内测 N≥30 家庭，"专属感"认同率 ≥60%；"都一样 / 鸡肋"类负面反馈占比下降 ≥50%。
  4. 回归风险控制：创作完成率不下降；生成成功率维持 ≥95%；0-2 岁链路不引入复杂选择。
