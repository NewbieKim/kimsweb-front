运营看板指标设计

围绕"家庭睡前陪伴链路"设计运营看板：北极星 + 护栏 + 八层指标框架，给出关键口径、数据基座补齐清单与 MVP 落地优先级。

记录时间：2026-08-25 ｜ 记录人：Nextapp 资深产品运营数字员工 ｜ 状态：方案已确认，待办延后（开发工期不足）

记录摘要

本次沟通明确了运营看板不应做成通用 DAU 看板，而应围绕家庭睡前陪伴链路设计：访问 → 登录 → 创作 → 生成成功 → 听故事 → 再次回来。产出北极星指标（每周成功生成故事的家庭数）、护栏指标（生成成功率 / TTS 失败率 / 内容不适率）和八层指标框架，并明确数据基座必须先补齐 page_view 与 tts_complete 等埋点。

✅核心结论：现有 operation-metrics 已具备概览 / 漏斗 / 稳定性骨架，运营看板是"扩展 + 补齐埋点"，不是从零重建。

对话背景

用户以资深产品运营数字员工身份提问："站在这个产品的角度，运营看板需要具备哪些内容"。本记录为指标与看板设计决策，按 skill 规则沉淀到时间线。

看板设计原则

  • 服务三种角色：运营周复盘、产品/开发定位体验与稳定性瓶颈、后续渠道投放归因。
  • 冷启动期指标宁精勿多：优先"生成漏斗 + 内容质量 + 反馈"，不做 DAU 虚胖。
  • 每个指标必须带口径（分子 / 分母 / 时间窗 / 去重键），否则看板是数字摆设。
  • 按"家庭"而非"登录用户"分析陪伴链路，因家长账号可能共用。
  • 体验指标（完播率 / 重复收听率 / 陪伴时长）比访问量更能回答"是否真的哄睡了孩子"。

指标框架总览

层级核心指标要回答的问题

护栏生成成功率、TTS 失败率、内容不适率体验是否崩、信任是否受损
概览UV、注册/登录、生成成功、TTS 播放、回访家庭本周整体怎么样
转化漏斗访问 → 登录 → 完成三步创作 → 生成成功 → 详情 → TTS → 回访用户卡在哪一步
体验留存TTS 播放率、完播率、重复收听率、平均陪伴时长、D1/D7故事是否真的哄睡了孩子
内容质量生成成功率、失败原因 TOP、主题热度、年龄分布、用户反馈哪个主题值得做内容

各层指标明细

转化漏斗（冷启动期最重要的页面）

链路：访问 → 登录/注册 → 进入创作 → 完成主角信息 → 完成梦境世界 → 完成成长主题 → 生成成功 → 进入详情 → TTS 播放 → 再次回访。

展示每一步的转化率与绝对流失数，异常下降时能定位到具体步骤。

体验与留存

  • TTS 播放率：播放用户 / 生成成功用户，衡量"生成的故事是否被真的听"。
  • TTS 完播率：播放进度 ≥80% 或最后一段播放完成的用户 / 播放用户。
  • 重复收听率：同一故事 7 天内播放 ≥2 次的用户 / 播放用户。
  • 平均睡前陪伴时长：单次会话内 TTS 累计收听时长。
  • D1 / D7 留存：按第 0 天生成成功的家庭回访口径。

内容质量

  • 生成成功率与失败原因 TOP（DeepSeek 超时 / 配额 / 格式错误等）。
  • 故事主题热度 TOP10：按生成量、完播率双维度。
  • 年龄组分布与各年龄组完播差异。
  • 用户反馈：评论情感倾向、不适内容举报数、抽检通过率。

用户与社区

  • 点赞 / 收藏 / 评论 / 关注行为数与人均行为数。
  • 续集创作率：完整听完故事后点击创作续集的比例，是 UGC 共创的前置信号。
  • 创作者活跃：本周生成 ≥3 个故事的家庭数。
  • 体验官 / 反馈表回收数。

渠道与商业化（后置）

  • 渠道：utm 参数 / 二维码 / 邀请码来源、各渠道漏斗对比。
  • 分享：分享次数、分享带来的新访问（K 因子）。
  • 商业化：积分发放/消耗/余额分布、解锁转化率、广告完成率与 eCPM、ARPU。

关键口径定义

指标口径
UV按 visitorId 去重；当前前端未生成/透传，属先决条件
注册转化率注册用户数 / UV
生成成功率成功 /（成功 + 失败），分母不能只算成功
TTS 完播率播放进度 ≥80% 或最后一段播放完成 / 播放用户
重复收听率同一故事 7 天内播放 ≥2 次 / 播放用户
D1 留存第 N 天回访家庭 / 第 0 天生成成功家庭

数据基座补齐清单

当前已埋：story_create、story_generate_success/failed、tts_play（服务端）。缺口：

  • page_view 前端埋点 + visitorId 生成与透传。
  • 创作三步事件（主角完成 / 梦境完成 / 主题完成），定位漏斗流失点。
  • tts_complete（完播判定）、story_detail_view、share_click。
  • 渠道参数（utm / 二维码 / 邀请码）进入事件 metadata。
🔴在 page_view 接通前，看板 UV 与漏斗数据为空转，不得作为运营结论依据。

MVP 落地优先级

批次内容前置条件
第一批概览 + 转化漏斗 + 稳定性补齐 page_view、漏斗事件、tts_complete
第二批体验留存 + 内容质量 + 用户反馈完播/重复收听数据累积 1-2 周
第三批渠道归因 + 商业化分享海报、广告/积分开关就绪

与现有实现的关系

现有 src/app/api/admin/operation-metrics/route.ts 已提供：概览（UV/注册/生成/TTS/反馈）、UV 漏斗、生成成功率、失败故事 TOP、7 天趋势。本方案是把它从"生成链路看板"扩展为"家庭睡前陪伴全链路看板"。
