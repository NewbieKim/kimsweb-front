已阅读 PM 同事的《上线复盘与新迭代方向》，关键对齐点：

定制化现状盘点（代码级）

环节现状问题
主角信息昵称、性别、4 个性格标签、年龄组、头像上传、伙伴（5 个默认 + 自定义 emoji）头像仅本地预览，不进故事；性格标签语义模糊（如"坚韧小战士"配兔子图标）
梦境世界4 张卡（海底泡泡城 / 外婆的魔法菜园 / 云朵面包房 / 恐龙快递站），含分龄设定与故事骨架封面为 Unsplash 通用图，数量少，难以产生"这是我家孩子专属世界"的感觉
成长主题36 个主题（4 维度），随机 9 个展示 + 自定义输入主题池够用，但缺少"今晚发生了什么"的场景化素材入口
Prompt 能力分龄硬约束、禁词、节奏 3:1、渐进降能、风味标签、情绪语气、家长晚安语、TTS 脚本风味标签（小百科/传统智慧/加油打气/搞笑/魔法）与情绪语气在 UI 完全无入口
输出呈现封面取自 5 张默认图池（storyId % 5），详情页正文 + TTS + 标签封面非定制；没有"专属故事卡"回显定制要素
档案与资产无孩子档案，每次创作重复填写；无故事宇宙/系列概念定制成本高、复用为 0、沉淀为 0

鸡肋原因诊断

  1. 定制不可见：家长填了大量信息，但生成后只有正文里出现名字这一个可见点；封面、卡片、详情都没有把"专属要素"显性化。投入感强、回报感弱。
  2. 输入输出感知落差：6 类输入与输出差异不成正比，AI 质量波动时故事甚至看不出定制痕迹，用户会认为"填了也白填"。
  3. 档案缺失 = 重复劳动：没有"孩子档案"，每次创作重新填一遍，定制从"一次建立反复使用"退化成了"每次登记"。
  4. 存在假定制：上传头像不进故事；封面是固定图池；伙伴只有 emoji。这些输入让用户期待差异化结果，但结果没有差异化。
  5. 能力未露出：prompt 已支持故事口味与语气，但 UI 没有入口，等于"有枪没子弹"，也浪费了差异化卖点。
💡一句话：定制化的价值不在"选项多"，而在"专属感"——孩子听到自己的名字、自己的生活、自己的伙伴；家长感到这是为我家孩子写的。

四条改造线

改造线核心思路候选动作
A. 让定制可见创作完成后立刻回显"我定制了什么"专属故事卡（主角形象 / 名字 / 伙伴 / 世界 / 主题 / 音色）；详情页主角卡；卡片封面体现主角；"给 XXX 的第 N 个故事"仪式感
B. 让定制省力一次建立，反复使用孩子档案（1 家庭 N 个孩子）：头像、昵称、年龄、性格、伙伴、偏好；创作时一键选"给谁讲"
C. 让定制真正影响故事把"今晚的事"编进故事今晚素材一句话（今天发生了什么 / 怕什么 / 想解决什么）；露出故事口味与语气；伙伴形象化（先 emoji 加强语义，后期插画）
D. 让定制有沉淀从单次故事变成情感资产同一主角的故事宇宙（第一集 / 第二集 / 系列）；成长记录与打卡；未来导出绘本 / 收藏

建议优先级：MVP = A + B + C 的基础版（档案 + 专属故事卡 + 今晚素材 + 口味语气露出）；P1 = 系列故事 + 伙伴形象；P2 = 打卡 / 导出 / 共创。

待确认问题

  • 定制化的首要目标是"家长感知"（分享/炫耀）还是"孩子感知"（名字/生活进入故事）？影响方案侧重。
  • 孩子档案是否允许存真实姓名与照片？默认匿名化展示还是家长可控公开？涉及隐私边界。
  • 今晚素材入口的形态：自由一句话，还是"情绪/场景卡片 + 一句话"？
  • 故事口味（风味标签）与语气是否全部露出，还是挑 3-4 个高频选项降低选择负担？
  • 是否把"故事宇宙/系列"纳入本期 MVP，还是先做单故事专属感？
