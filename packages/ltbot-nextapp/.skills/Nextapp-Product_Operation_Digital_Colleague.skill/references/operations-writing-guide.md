# 运营方案写作指南（运营 → 产品需求汇总）

> 用户指定规范（2026-08-25 收录）：编写运营方案、需求汇总、调研报告时遵循本指南。配合场景卡片库示例使用：`records/20260825场景卡片示例.html`。

## 适用场景

- 运营侧向产品团队提出改进需求的汇总报告。
- 深度定制化、内容、增长、数据等运营专题调研。
- 需要产品经理直接拿去写 PRD 的需求文档。

## 标准结构（九段式）

### 一、背景概述

一句话说明"为什么写这份文档"：基于哪些反馈/观察/数据，发现哪些维度有优化空间，给产品团队做什么。

### 二、问题总览

- 按紧急程度分类：🔴 高（影响核心体验/有数据支撑）、🟡 中（影响留存/满意度）、🟢 低（锦上添花/长期），给出各项数量。
- 按问题类型分布：交互体验 / 内容质量 / 功能缺失 / 数据算法，给出各项数量。

### 三、运营目标与期望

用"改进后希望达成"的句式，量化目标（例：完播率 62% → 80%）。无基线时明确标注"待埋点上线后校准"，不虚构数字。

### 四、问题清单（核心章节）

每条问题统一格式：

```text
问题编号：OP-xxx
问题标题：一句话概括
问题类型：交互体验 / 内容质量 / 功能缺失 / 数据算法
优先级：🔴高 / 🟡中 / 🟢低

1. 问题描述（发生了什么）
2. 影响范围与严重性
3. 数据支撑（如有；可用代码级证据，无数据时标注"待埋点"）
4. 用户声音（真实原话优先；预演场景需标注"待验证"）
5. 改进建议（方案 A/B + 建议优先级 + 预估工作量）
6. 预期价值（改了能得到什么）
```

### 五、需求优先级矩阵

表格：优先级 / 问题编号 / 问题标题 / 预估工作量 / 预期收益 / 建议排期。

### 六、典型案例详述

选 1-2 个典型用户故事：用户画像、使用场景、遇到的问题、期望的改进。让产品经理"共情"。

### 七、竞品参考

行业成熟做法或内部对标（如场景卡片库示例），未实测的标注"待补充调研"。

### 八、改进成功标准

与产品共同定义验收：功能验收 / 数据验收 / 用户反馈验收 / 回归风险控制。

### 九、附录

证据清单、埋点需求、调研问卷、竞品对比表、脱敏访谈记录。

## 写作五原则

1. **数据先行，不是感受先行**：写"数据显示 X"而不是"我觉得 X"；无数据时给出代码级证据或明确标注待埋点。
2. **区分运营观察与用户需求**："我认为"是观察，"用户说 + 数据表明"才是需求。
3. **每条需求说清"改了能怎样"**：只提问题不提收益等于没有需求。
4. **主动给方案，不只抛问题**：给出方向性方案和预估工作量，让产品有抓手。
5. **用产品经理听得懂的语言**：多用"场景、路径、漏斗、留存、复用率"，少用运营黑话。

## 数据纪律

- 不虚构用户证言；预演类表达必须标注"待真实反馈验证"。
- 无埋点基线时，目标值标注"待基线校准"，不可写成已达成事实。
- 引用代码作为证据时给出文件与机制（如 `storyId % 5` 封面池）。
