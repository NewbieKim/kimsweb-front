# ltbot H5 移动端响应式改造清单

> 基于 `packages/ltbot` 当前源码评估。`pnpm --filter ltbot run build:skip-ts` 可正常构建通过（约 1 分钟，仅有 Sass legacy API 与 chunk 体积告警）。

## 1. 可行性结论

整体改造**可行，且不需要重构技术栈**。工程是 Vue 3 + Vite + Pinia + Tailwind，具备做响应式 H5 的基础。

- 已经有一部分页面做了基础响应式，例如 `views/workbench/new.vue`、`views/aiWorks/index.vue`、`views/blog/index.vue` 有断点处理。
- 主要问题集中在全局布局外壳（固定 64px 顶部导航、`100vh`、无安全区处理）和少数桌面优先页面（技能知识库、聊天、博客、欢迎页、睡眠空间 iframe）。
- 真正的业务风险不在 Vue 本身，而在两处不可完全控制的 iframe 内容：
  1. 技能知识库预览的 HTML 文档本身是否响应式；
  2. `space.ltbot.top` 睡眠空间页面是否响应式。

建议按“外壳优先、P0 功能优先、页面逐个收敛、最后真机验收”的方式推进。

## 2. 移动端现状问题清单

### P0：会直接阻断核心功能

#### 2.1 AI 悬浮按钮在手机上点击无反应

- 位置：`src/layout/index.vue:29`
- 原因：按钮同时绑定了 `@click="handleAIFloatClick"` 和 `@touchstart.prevent="handleAIFloatPointerDown"`。移动端 `touchstart` 上 `preventDefault()` 会抑制后续合成 `click`，因此手指点击后只进入拖拽逻辑，`handleAIFloatClick` 不会触发，聊天侧边栏不弹出。
- 建议：改用 Pointer Events 统一处理，或在 `touchend` 中按移动距离判断“轻点”并主动打开；不要把 `touchstart` 直接 `preventDefault()`。

#### 2.2 顶部导航布局错乱

- 位置：`src/layout/components/topNav.vue`
- 现象：截图里“工作台/技能知识库/睡眠空间/关于我”逐字竖排、溢出导航栏；右侧刷新图标被屏幕裁掉一半。
- 原因：
  - `.top-nav` 是 `display: flex` 且不换行，左右内容总宽远超 375px；
  - `.nav-link` 没有 `white-space: nowrap` 和 `flex-shrink: 0`，被压缩后中文逐字换行；
  - `.right-menu` 有 6 个图标，无移动端折叠策略；
  - 没有任何 `@media (max-width: ...)`。
- 建议：
  - 移动端改为“Logo + 汉堡菜单 + AI 入口”，其余导航放入抽屉或底部导航；
  - 隐藏 `Run Demo` 这类开发入口；
  - 所有导航项设置 `white-space: nowrap`，避免单字折行；
  - 导航高度按安全区处理，不再写死 64px。

#### 2.3 技能知识库菜单与渲染区错乱

- 位置：`src/views/skillKnowledgeBase/index.vue`、`src/views/skillKnowledgeBase/components/KbToolbar.vue`、`KbSplitEditor.vue`
- 现象：菜单列表和正文上下堆叠后互相压盖，正文标题下方出现大段空白，文字被裁切。
- 原因：
  - 移动端 media query 只做了“侧栏变 220px 高、正文 min-height 60vh”的简单堆叠，没有把菜单变成抽屉或可收起面板；
  - `.kb-page__body` 没有固定高度，`iframe height: 100%` 在父容器高度为 `auto` 时无法可靠撑开，导致正文区域塌陷/空白；
  - `KbToolbar` 的路径、预览/编辑、更多按钮在 320-375px 下容易溢出；
  - `KbSplitEditor` 没有任何移动端规则，编辑态仍是左右各 50%，手机上不可用。
- 建议：
  - 菜单在移动端改为横向滚动条/顶部下拉/抽屉，默认收起；
  - 正文容器给固定视口高度，例如 `height: calc(100dvh - 导航 - 工具栏)`，并允许内部滚动；
  - 工具栏允许换行，路径文本截断；
  - 编辑态在移动端改为“预览/源码 Tab”或上下堆叠；
  - 评估 iframe 内文档是否要加 `transform: scale()` 预览模式，或要求文档本身响应式。

### P1：会严重影响移动端体验

#### 2.4 全局视口与安全区

- 位置：`index.html`、`src/style.css`、`src/layout/index.vue`、`src/layout/components/mainContain.vue`
- 问题：
  - `index.html` 没有 `viewport-fit=cover`，刘海屏/全面屏下固定顶部导航会贴近状态栏；
  - 大量使用 `100vh`，移动浏览器地址栏收起/展开时页面高度跳动；
  - 页面内还有自己的 sticky 头部（如博客 Tabs），`top: 0` 会和全局 fixed 导航重叠。
- 建议：
  - viewport 增加 `viewport-fit=cover`；
  - 用 `100dvh`/`100svh` 代替部分 `100vh`；
  - 引入 `env(safe-area-inset-top/bottom)`，统一导航高度变量；
  - 页面内 sticky 元素按 `top: var(--nav-height)` 偏移。

#### 2.5 聊天页仍是桌面版

- 位置：`src/components/ChatBot/index.vue`、`src/views/chat/index.vue`
- 问题：`.chat-box` 固定 `height: 600px`，侧边栏固定 `width: 260px`；在 375px 手机上主聊天区只剩约 115px，输入框按钮还会重叠。该页面并非死代码，工作台 Agent 提交会跳转到 `/chat`。
- 建议：移动端改成全屏聊天布局，历史会话用抽屉/底部弹层，输入区固定底部并处理安全区与软键盘。

#### 2.6 博客列表强制 960px 最小宽度

- 位置：`src/views/blog/index.vue:480`
- 问题：`.content-container { min-width: 960px }` 导致手机必然横向滚动；下面的 `@media` 只调整了 padding，没有重置这个宽度。
- 建议：移动端改为 `width: 100%; min-width: 0; max-width: 960px`，并让列表卡片纵向堆叠。

#### 2.7 欢迎页/落地页固定 600px

- 位置：`src/views/welcome/index.vue:171`
- 问题：登录按钮层固定 `width: 600px`，配图 260px、标题 35px，手机 375px 必然溢出；Three.js 只按初始化尺寸创建，旋转/窗口变化不会重设画布。
- 建议：宽度改为 `min(90vw, 600px)`，图片/字号响应式；增加 resize/orientation 监听；低端机考虑跳过 3D 或降级静态背景。

#### 2.8 睡眠空间 iframe 全屏盖住导航

- 位置：`src/views/createSpace/index.vue`
- 问题：容器固定 `100vw / 100vh`，而外层布局已有 64px 顶部导航，iframe 会顶到导航下面；`adjustIframeHeight` 用 `document.documentElement.scrollHeight - 50` 设置 iframe 高度，移动端行为不可靠。
- 建议：移动端改成独立全屏路由（隐藏全局导航），或明确 `height: calc(100dvh - nav)`；`space.ltbot.top` 本身如果不是响应式，需要单独立项。

#### 2.9 RemoteChat 开发/测试环境 API 地址写死 localhost

- 位置：`src/components/RemoteChat/index.vue`
- 问题：`LOCALURL = 'http://localhost:6688/api'`。手机通过局域网 IP 访问时，浏览器会把请求打到手机自身的 6688 端口，聊天必然失败。
- 建议：用 `window.location.origin` 或 `VITE_REMOTE_CHAT_API` 注入，生产与本地联调都不要再写死 localhost。

### P2：体验与工程质量问题

- 用户页在 769-1024px 区间：`height: 100vh + overflow: hidden`，但内容已经切成单列且 `min-height: 600px`，内容可能被裁掉。需要让该区间也允许滚动。
- `RemoteChat` 嵌入 AI 侧边栏后，头部包含标题加 4 个图标按钮，320px 下会比较挤；需要让标题截断、按钮间距收紧。
- 博客编辑器在移动端有 media query，但 Markdown 工具栏和发布弹窗仍需要真机验证；工具栏过长时应允许横向滚动而不是撑破页面。
- `topNav` 的“Run Demo”入口是开发演示，不应出现在移动端正式导航里。
- 全屏按钮在 iOS Safari 上不受支持，移动端应隐藏或降级为无操作。
- Tailwind 配置里 `width/height/fontSize/spacing` 用 `rem` 生成了 0-750/1448 的巨型数值类名，若有人按“px 数值”使用（例如 `w-100` 实为 100rem），会直接撑爆布局。建议改为语义化 token，或全项目统一 px 转 vw/rem 方案。
- 构建产物偏大：单个 CSS 约 1.6MB，主 JS chunk 约 1.8MB。移动端 H5 需要关注首屏体积、代码分割、图片懒加载和长列表性能。
- 技能知识库 iframe 文档、`space.ltbot.top` 两个外部内容源无法靠当前仓库的 CSS 完全修复，需要在清单中明确边界。

## 3. 分阶段改造清单

### 阶段 0：定基线（建议 0.5 天）

- 用 Playwright/真机建立 320、375、414、768、1024 五档截图与自动化检查。
- 自动化断言：`document.documentElement.scrollWidth <= window.innerWidth`，即页面不能横向溢出。
- 确定移动端信息架构：
  - 保留哪些一级入口；
  - AI 入口放导航还是悬浮球；
  - 睡眠空间是打开新标签页还是应用内跳转。
- 确认技能知识库 iframe 文档的响应式边界：是改文档本身，还是移动端用缩放预览。

### 阶段 1：全局外壳 + AI 交互（1-2 天）

- [ ] `index.html`：补充 `viewport-fit=cover`、`theme-color`，标题从 Aion 统一为产品名。
- [ ] `src/style.css`：增加 CSS 变量（导航高度、安全区、断点），`#app` 全局防横向溢出，移动端根高度使用 `100dvh`。
- [ ] `src/layout/index.vue`：移动端导航高度与安全区；AI 悬浮球改 Pointer Events，点击/拖拽分离；默认放右下角，不遮挡正文。
- [ ] `src/layout/components/topNav.vue`：移动端换成 Logo + 汉堡菜单 + AI 按钮，导航链接收进抽屉；所有链接 `white-space: nowrap`；隐藏 `Run Demo` 和 iOS 不支持的全屏按钮。
- [ ] `src/components/AISidebar.vue`：移动端改为全屏/底部抽屉，带安全区 padding；关闭时清理滚动锁。
- [ ] `src/components/RemoteChat/index.vue`：API 地址改为环境变量或 `window.location.origin`；移动端头部紧凑化，历史会话面板全屏化。

### 阶段 2：核心页面逐个响应式（3-5 天）

- [ ] 技能知识库：
  - 菜单移动端改为可收起抽屉/顶部下拉；
  - 预览区固定视口高度，iframe 不再塌陷；
  - 工具栏换行；
  - 编辑态移动端改为预览/源码 Tab；
  - 决定 iframe 文档的缩放策略。
- [ ] 聊天页：
  - 全屏聊天，历史会话抽屉化；
  - 输入区固定底部并处理安全区/软键盘；
  - 移动端隐藏宽侧边栏。
- [ ] 博客：
  - 去掉 `min-width: 960px`；
  - Tabs 偏移全局导航高度；
  - 移动端卡片纵向堆叠；
  - 编辑器工具栏横向滚动/换行。
- [ ] 工作台：
  - 复用现有断点，重点检查 Hero 控制台、TODO 面板、Tool Matrix、项目网格在 375px 的间距与触摸目标。
- [ ] AI 艺术廊：
  - 现有断点基本可用，重点验证 lightbox 和视频弹窗在手机上的关闭、滑动、滚动锁清理。
- [ ] 用户页：
  - 769-1024px 区间允许滚动，不再裁切内容。
- [ ] 欢迎页：
  - 登录按钮层宽度改为 `min(90vw, 600px)`；
  - Three.js 增加 resize/orientation 处理；
  - 低端机降级。
- [ ] 睡眠空间：
  - 移动端独立全屏或正确计算 iframe 高度；
  - 与 `space.ltbot.top` 团队确认外部页面响应式计划。

### 阶段 3：H5 硬化与验收（1-2 天）

- [ ] 全站触摸目标不小于 44x44px。
- [ ] 输入框字号保持 16px 以上，避免 iOS 聚焦自动放大。
- [ ] 页面滚动与弹窗滚动锁不互相冲突。
- [ ] 旋转屏幕后页面布局与 Three.js 画布正确重算。
- [ ] 真机覆盖：iOS Safari、Android Chrome/微信内置浏览器。
- [ ] 性能：首屏按路由拆包、图片懒加载、减少主 bundle。
- [ ] 回归桌面端：所有改动不得破坏 1024/1440px 桌面布局。

## 4. 验收清单

以下每项在 320、375、414、768 四档通过才算完成：

- 页面无横向滚动。
- 顶部导航不折行、不裁切、不遮挡内容。
- 点击 AI 悬浮按钮在手机上能打开聊天侧边栏。
- 技能知识库：菜单可展开/收起，选择文档后预览区正常撑开，工具栏不溢出，编辑态在移动端可用。
- 聊天页：能发送消息、切换历史会话，输入区不被键盘遮挡。
- 博客：列表、编辑、发布弹窗无溢出。
- 欢迎页：落地内容完整可见，旋转后正常。
- 睡眠空间：iframe 高度正确，不盖导航或改为全屏路由。
- 桌面端回归：导航、技能知识库、聊天、博客、工作台原有行为不变。

## 5. 非目标

- 本清单不包含产品逻辑重构，例如导航结构、页面职责、聊天协议调整。
- 不包含 `ltbot-server`、`ltbot-uniapp`、`ltbot-nextapp` 等其他工程的移动端改造。
- 不包含对 `space.ltbot.top` 与技能知识库 HTML 文档的内容重写，这部分需要单独评估。
