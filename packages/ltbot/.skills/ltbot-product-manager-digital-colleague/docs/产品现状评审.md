# ltbot 产品现状评审

> 2026-09-16，数字同事重建时进行的源码走查。以下“建议”均待用户确认，不是已决定的路线图。

## 已核实

- 工作台是聚合入口，新版页面由静态工具/资讯/资源数据与真实待办面板组成。
- AI 对话有工作台跳转的 `/chat` 页面和全局悬浮侧栏两套入口。
- 技能知识库围绕 HTML 浏览与编辑；博客列表含 mock，编辑器含本地自动保存。
- 睡眠空间是外站，不是 ltbot 的原生页面业务。

## 体验问题候选

| 优先级建议 | 观察 | 需验证的问题 |
| --- | --- | --- |
| P1 | 双聊天入口 | 用户能否理解两处入口的差异？历史会话是否符合预期？ |
| P1 | 静态工具/工作流卡片 | 文案是否让用户误以为点开即可执行完整 AI 流程？ |
| P1 | 顶部工作台跳转大小写 | `/workBench` 与路由 `/workbench` 在当前环境是否正常匹配？ |
| P2 | 外站睡眠空间 | 新标签与 iframe 两种入口是否需要统一说明？ |
| P2 | 博客 mock 初始内容 | 用户是否能辨别示例文章与真实内容？ |

## 建议的低成本验证

先用浏览器走查五个高频任务：进入工作台、发起对话、管理待办、打开知识库文档、保存博客草稿。记录每步实际反馈和失败状态，再确定是否要改导航、合并聊天或调整卡片文案。不要在走查前承诺效果指标。
