# ltbot 产品基线

> 最后核对：2026-09-16。此文件只收录从 `packages/ltbot` 前端源码能确认的事实；市场、用户和线上效果仍待调研验证。动态需求与决策见 `requirements/`。

## 定位与使用场景

界面以 **Aion / lt-bot** 展示，当前形态是个人 AI 效率工作台：用户从欢迎页进入工作台，搜索或发起 AI 对话、处理待办、访问工具/工作流/项目资源，也可查看博客、技能知识库、艺术廊和个人介绍。工作台文案提出“AI 先完成第一版”“自动推荐工具、拆解任务”等愿景，但不能据此推断全部工作流已执行。

目标用户的具体职业、使用规模、留存和商业模式没有足够的代码证据。可作为设计假设的场景：日常信息查找、研发/办公辅助、待办整理、项目文档阅读。后续调研应让真实用户或数据验证。

## 功能现状表

| 模块 | 当前前端形态 | 产品判断边界 |
| --- | --- | --- |
| 欢迎页 | Three.js 视觉，点击进入工作台 | 是进入页，不是账号登录。 |
| 工作台 | 新版 `workbench/new.vue` 聚合 Hero、搜索、待办、工具、工作流、资讯、项目/资源卡片 | 多数内容来自本地静态数据；待办接服务端。 |
| AI 对话 | `/chat` 独立页面与全局悬浮侧栏 `RemoteChat` | 两套入口和实现，不能笼统称为同一个已验证功能。 |
| 待办 | 工作台面板可获取、新建、更新、删除 | 前端 Store 走 `/api/agencies`，最终可用性依赖服务端。 |
| 技能知识库 | HTML 文档树、预览、编辑、保存、下载 | 走 `/api/skillKnowledgeBase`；生产编辑锁需实际验证。 |
| 博客 | 列表与 Markdown 编辑器，支持草稿/发布操作 | 列表混有 mock 初始内容，真实文章依赖 `/api/articles`。 |
| AI 艺术廊 | 图片/视频展示 | 页面数据以示例数组为主，不应承诺真实 AI 生成。 |
| 睡眠空间 | 顶部导航打开 `space.ltbot.top`；另有 iframe 页面 | 是跨站入口，本包不实现故事/睡眠业务。 |
| 个人介绍 | `/user` 页面 | 导航可达；不等于完整账户中心。 |
| Run Demo | 顶部导航调用 `hooks/mockAgent` 演示 | 教学/演示代码，不宜作为面向用户的生产能力承诺。 |

## 信息架构和体验约束

- 路由是 hash history；实际导航入口以 `src/layout/components/topNav.vue` 为准。路由存在不等于菜单已开放。
- 顶部导航与布局内 AI 悬浮按钮共同构成全局外壳。设计新需求先核对这些入口与工作台 Hero 的引导。
- 工作台的“Agent 对话/搜索/社区/生活/站内文章”是同一 Hero 内的 tab；不同 tab 会跳内部路由或外部搜索，不能假定都有站内处理结果。
- 产品方案必须区分静态展示、外部跳转、真实接口、演示链路及需联调的能力。原型和 PRD 按这五种状态标注。
- 对网络、流式中断、空数据、未保存编辑和外站失败写明确状态；不要只设计正常路径。

## 未确认事项

- 主要目标用户及高频任务排序；是否以个人工具站、团队工作台或公开产品为主要方向。
- 独立聊天与悬浮侧栏的长期分工，以及会话共享的目标体验。
- 工作台静态工具与工作流卡片的优先级：仅作内容导航，还是逐步变成可执行任务。
- 生产环境知识库编辑策略、后台权限与外站承接体验。

这些是待确认的问题，不是已获授权的产品计划。
