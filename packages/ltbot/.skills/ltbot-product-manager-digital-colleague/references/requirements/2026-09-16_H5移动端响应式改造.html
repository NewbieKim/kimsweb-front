ltbot H5 移动端响应式改造 PRD

日期：2026-09-16 · 当前版本：v0.2.0 · 状态：用户已确认本期范围及手机保留 AI 悬浮球；页面交互细则为产品方案，供开发拆解与评审 · 当前 PC / 手机原型 · v0.1.0 来源材料，非当前开发依据

1. 用户确认与问题定义

用户在 2026-09-16 明确确认：本期只考虑工作台、技能知识库、睡眠空间、关于我四块功能；手机端继续保留截图所示的 AI 悬浮球和聊天组件；聊天采用当前在用的 RemoteChat，ChatBot 不纳入本次设计和验收。欢迎页作为进入工作台的既有入口，只做“可进入”的兼容检查，不作为第五块功能。博客、AI 艺术廊、独立 /chat 页面及其历史会话不在本期范围。

当前问题：全局导航固定 64px，手机宽度下整排文字与右侧图标挤压；AI 球的 touchstart.prevent 可能阻断轻点产生的 click；知识库目录、预览和编辑器为桌面组织；外站睡眠空间的 iframe 深链用 100vh，与全局顶栏叠加；关于我在平板区间固定视口高度且隐藏溢出。来源为改造清单与 2026-09-16 源码核对。附图说明了用户期望的手机工作台 AI 悬浮球；其位置是视觉参考，交付时需避让输入与操作控件。

本地 Chromium 375×812 走查时，工作台可渲染，知识库目录接口返回错误，未能验证真实 HTML 预览。该结果只反映本地服务状态，不推断线上功能不可用。RemoteChat 目前通过 AISidebar 以 embedded 模式嵌入，发送使用 /api/chatAgent，会话由 chat store/API 管理；开发环境 API 地址存在 localhost 写死问题。工作台 Agent 提交当前会跳 /chat?prompt=...，与本期选用 RemoteChat 的入口目标不一致。

2. 目标、非目标与成功信号

目标：手机用户从现有入口进入工作台，使用四项导航访问工作台、知识库、睡眠空间、关于我；可随时轻点悬浮 AI 球打开 RemoteChat，发送消息、查看历史并回到原页；PC 四项功能保持可用。所有关键操作在 320–414px 手机宽度和刘海/底部手势区内可见、可点击。

非目标：ChatBot 与独立 /chat 的移动适配；博客、AI 艺术廊、Run Demo 的功能改造；静态工作流卡片变为真实执行；重写知识库 HTML 文件本体或 space.ltbot.top 页面；新增 AI 协议、会话迁移或跨包功能。既有深链仍可访问时，不能让其破坏四块功能的导航与布局，但不扩大业务范围。

可观察完成信号：320、375、414、768、1024、1440px 的四项路径无页面级横向滚动；手机 AI 球轻点可靠打开、拖动不误开、关闭后页面可滚动；知识库选文档与预览可用；关于我内容可完整纵向浏览；睡眠空间入口能明确离站且失败有返回/手动打开路径；真实手机上 RemoteChat 能通过实际后端发送、加载历史并处理错误。PC 1024/1440px 回归四项功能。

入口规则：工作台 Hero 的“Agent 对话 / 开始执行”属于四块范围内的操作，点击后打开同一个 RemoteChat，并把已输入文本带入草稿，由用户在聊天面板内点击“发送”；不跳 /chat，也不自动发送，避免出现两套聊天行为。现有 RemoteChat 只暴露 embedded 属性与 close 事件，尚无可靠的“外部传入草稿”接口；开发需补充组件受控草稿/公开方法或等效适配，并验证会话切换时草稿不串。空文本时提交无动作并保持焦点。Hero 其他 tab（搜索、社区、生活、站内文章）沿用现有显示和去向，手机端按截图完整排布；这些路径不纳入本期新增功能验收，不能将其文案理解为已实现的 AI 执行能力。

AI 球定位：默认靠右、位于底部安全区上方，点击区域至少 44×44px。截图中的球位于 Hero 右侧，开发实现须在 320/375px 下不盖住“开始执行”、待办操作、知识库工具栏等关键按钮。可拖动时使用 Pointer Events 区分轻点与位移，释放后吸附到屏幕左右安全边界并在横竖屏切换时重新约束位置；打开聊天时隐藏球。点击与拖动都应保留键盘可访问性及 aria-label。

全局使用动态视口高度和 env(safe-area-inset-*)；顶栏下方内容有明确偏移。页面允许纵向滚动，不能只用根节点 overflow-x:hidden 掩盖超宽元素。菜单、聊天、知识库目录一次只出现一个最上层浮层；开启时锁背景滚动，关闭、路由切换及组件卸载后恢复。关闭按钮、遮罩点击与 Escape 应可关闭浮层并将焦点返回触发元素。触摸目标建议至少 44×44px；手机输入字号至少 16px，防止 iOS 自动放大。

4. 四块功能详细需求

4.1 工作台（P0）

进入：从欢迎页现有入口或四项导航进入 /workbench。欢迎页只验收按钮与标题不溢出，3D 视觉失败不妨碍进入；不是账号登录。工作台首屏能看到 Hero 标题、Agent 输入与“开始执行”。手机内容顺序为 Hero → AI 待办 → 工具/工作流/资讯/项目资源；后四类卡片按单列或合理双列排列，不横向撑开。工具与工作流多为静态展示，原型标明“展示内容”，不作为本期执行能力。

Agent 路径：输入文本后点“开始执行” → 打开 RemoteChat 全屏层 → 草稿可见，用户确认后发送 → 显示用户消息、流式反馈/失败状态。直接点 AI 球则打开当前 RemoteChat 会话，不预填新文本。重复点击“开始执行”不得创建重复会话或重复发送。用户在聊天面板关闭后，回到工作台原滚动位置，未发送草稿按 RemoteChat 既有持久策略保留。

待办：继续复用 agency store 的真实 API。加载显示进度；零项显示“暂无待办”与新增入口；网络失败显示错误和重试，不把错误当空列表。新增、完成、删除在接口成功后更新；失败时回滚或保留原项并明确提示。手机弹窗在键盘弹出后仍可完成保存/取消。

4.2 技能知识库（P0）

进入：四项导航进入 /skillKnowledgeBase。手机顶部显示“选文档”、当前文档名（省略号截断，全称可查看）和操作区；目录从侧边抽屉打开，默认收起。PC 保留目录树 + 正文分栏。目录与文件分别有加载、空、错误/重试状态。选择文档后目录收起并加载预览；预览容器占据导航与工具栏之外的可视空间，iframe 在容器内滚动，不塌陷或被压住。

编辑边界：当前源码对生产构建设置编辑锁，须以真实构建确认。若目标环境允许编辑，手机采用“预览 / 源码”单页 tab，源码区可输入，保存/取消操作可见；PC 保留分栏编辑。保存中禁用重复操作，失败保留源码并允许重试，成功后刷新预览。切文档、关编辑、离开页面时若内容未保存，提示继续编辑或放弃修改。若生产锁定，隐藏或禁用编辑并明确“当前环境仅支持预览”。HTML 文档本身不响应式时不默认整体缩放，可从更多操作“在新标签打开原文”；问题文档单独列清单，不算外壳改造完成证明。

4.3 睡眠空间（P1）

进入：四项导航中点击“睡眠空间 ↗”后按现有行为在新标签打开外部 space.ltbot.top，原工作台页面保留。浏览器拦截新标签时显示说明与可手动点击的外链；外部站点加载失败时用户仍能回到 ltbot。该站点内容、业务与自身响应式不由当前仓库保证，应记录独立验收结果和对接事项。

深链：当前 /createSpace iframe 路由仍存在。若用户直接访问，页面不能以 100vh 盖住全局导航；提供“打开睡眠空间网站”与“返回工作台”。是否最终移除 iframe 路由，须做现有链接使用情况评估，本期不直接删路由。

4.4 关于我（P1）

进入：四项导航进入 /user。手机将个人信息卡与资料卡按顺序单列；769–1023px 以及手机均允许内容自然纵向滚动，不能由 height:100vh + overflow:hidden 裁切。动态卡片点击、头像/联系信息等现有可见交互保持可用；图片失败时保留文字，不影响阅读。背景装饰不得挡点击或增加页面横向宽度。

逐项验收：

1. 320、375、414、768、1024、1440px 对欢迎入口、工作台、知识库、关于我、/createSpace 深链断言 document.documentElement.scrollWidth <= innerWidth；允许明确设计的组件内横向滚动。

2. 375px 打开菜单只见四项业务入口，选择后能进入正确页面并关闭抽屉；顶栏无逐字换行，操作不被刘海区遮住。PC 四项导航正常。

3. 320px 工作台 AI 球轻点一次打开 RemoteChat；拖动 20px 不误打开；默认/拖后位置不盖“开始执行”与待办按钮。聊天打开时球隐藏；关闭后原页可滚动。

4. Hero 输入“整理周报”后点击“开始执行”：RemoteChat 草稿显示该文本且网络未发出消息请求；用户点击发送后真实 SSE 请求仅一次。点击 AI 球直接打开现有会话；不进入 /chat 或实例化 ChatBot。

5. RemoteChat 在网络正常、断网、历史为空、历史加载失败、切会话与软键盘弹出情况下，状态和按钮可见；关闭重开时草稿/当前会话按已确认策略保留。

6. 知识库目录加载/空/错、文档加载/错各有区别；选文档后 iframe 可阅读。允许编辑环境下保存成功/失败、切文档的未保存提醒通过；生产编辑锁经构建确认。

7. 睡眠空间点击出现新标签；弹窗拦截时有手动外链。/createSpace 深链不盖顶栏；关于我在 768/1024px 可滚到最后一项。

8. 横竖屏切换、地址栏收起/展开、软键盘和连续打开/关闭菜单/聊天三次后无位置错乱与残留滚动锁。

建议埋点需遵循现有统计方案：四项导航点击、AI 球打开/关闭、Hero 转 RemoteChat、发送结果、知识库文档加载结果、外站点击结果。只记录入口、路由、结果与视口区间；不采集聊天正文或知识库内容。

7. 风险、待核实与变更记录

  • 知识库 HTML 文档和 space.ltbot.top 是独立内容源；外壳合格不代表内层内容已响应式。需列出具体失效文档/外站页面再分派。
  • 截图右侧 AI 球紧邻 Hero 输入区域，原位复制可能挡操作。以“入口始终可用且不遮挡主操作”为实现准则，具体像素位置可随安全区和滚动改变。
  • 工作台 Hero 的其他 tab 现有代码仍会打开外站或跳博客；本期不开发这些路径，但保留现有入口与基础可见性，避免响应式改造意外删除原有页面内容。
  • RemoteChat 当前没有外部预填草稿契约；开发需选择最小接口并验证 SDK PromptInput 的生命周期。若无法安全预填，不能悄悄改成跳 /chat，应反馈技术限制并评审替代文案。
