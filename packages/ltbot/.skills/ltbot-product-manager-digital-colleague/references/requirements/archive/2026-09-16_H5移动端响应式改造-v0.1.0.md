# ltbot H5 移动端响应式改造 PRD

> 日期：2026-09-16 · 版本：v0.1.0 · 状态：产品方案待评审，可供研发估时与技术拆解；评审确认后升为开发基线 · 原型：[PC / 手机交互原型](../prototypes/ltbot-H5响应式改造-v0.1.0.html)

## 1. 背景与证据

当前站点是 Vue 3 / Vite 的 AI 效率工作台，核心路径包括欢迎页、工作台、独立 `/chat`、全局 AI 侧栏、技能知识库、博客与外站睡眠空间。已有部分页面设置断点，但全局导航、独立聊天、知识库和博客仍按桌面宽度组织。2026-09-16 在本地 Vite、Chromium 375×812 下走查：`/chat` 文档宽 447px，`/blog` 文档宽 960px，均产生横向溢出；知识库目录 API 无可用响应，现场只验证了错误态，不能证明文档预览已可用。工作台可渲染，但顶部仍完整展示桌面导航。此处是本地环境观察，不等于线上故障统计。

源码证据：`src/layout/index.vue` 的 AI 球在 `touchstart.prevent` 后依赖 `click` 打开；`topNav.vue` 固定 64px 且未折叠；`ChatBot/index.vue` 固定 600px 高、260px 侧栏；`blog/index.vue` 设置 `min-width: 960px`；知识库编辑器左右 50% 且未设移动断点；`createSpace/index.vue` 以 `100vh` 嵌入外站。既有[改造清单](../../docs/H5移动端响应式改造清单.md)作为问题输入，具体实现须再以最新源码确认。

## 2. 目标、用户与边界

**目标**：手机浏览器中完整进入工作台、打开 AI、发送及切换独立对话、查阅知识文档、浏览/编辑博客和访问外站入口；常用操作不被导航、键盘、刘海区或浮层遮挡。PC 原有路径与可见功能继续可用。此次是响应式体验升级，不承诺新增 AI 能力。

**场景假设，待真实用户验证**：通勤或离开电脑时，个人用户用 375px 手机查看待办并快速问 AI；研发/办公用户临时查知识文档；内容维护者用手机查看博客、必要时修改草稿。现有代码不能证明这些人群的规模与频率。

**成功判据**：320、375、414、768、1024、1440px 的指定路由没有页面级横向滚动；P0 流程能在 iOS Safari、Android Chrome 与微信内置浏览器完成；PC 1024/1440px 回归无功能倒退。真实接口故障时显示可理解的错误与重试入口，不以 mock 成功替代联调。

**本期不做**：重构聊天协议或合并两套会话；重写知识库 HTML 文档本体、`space.ltbot.top` 或其他包；把静态工具/工作流卡片改成可执行任务；新增账户、权限、AI 推荐能力。外站及嵌入文档是否响应式需独立验收或另立项。

## 3. 方案总览与信息架构

| 区域 | 手机 ≤768px 提案 | PC ≥1024px | 数据/性质 |
| --- | --- | --- | --- |
| 全局顶栏 | 安全区下方：菜单、Aion/工作台、AI；不展示整排导航 | 保留现有横向导航，修正挤压及焦点 | 路由/外站入口 |
| 菜单抽屉 | 工作台、技能知识库、博客、AI 艺术廊、关于我、睡眠空间；打开时锁背景滚动，选中后关闭 | 不另开抽屉 | 内部路由与外站明确区分 |
| AI 快捷入口 | 顶栏 AI 为唯一固定入口；移除手机悬浮球，避免挡正文/键盘；打开全屏 `RemoteChat`，关闭回到原页 | 保留可拖动 AI 球及侧栏 | 真实会话，依赖 API |
| 工作台 Agent | 输入后跳独立 `/chat?prompt=…`，目标页只预填，用户再次点击发送；文案改“进入对话” | 同一语义 | 独立聊天；与侧栏不共享会话的现状须明确 |
| 睡眠空间 | 菜单中标“外部网站”，新标签打开；被拦截则提供可点击原始链接 | 维持新标签 | `space.ltbot.top` 外站 |

在 769–1023px 使用可折叠菜单与可滚动内容，避免半宽桌面导航与用户页裁切。断点为本 PRD 的建议值，研发可在不改变行为的前提下依据布局微调并记录。

### 3.1 全局约束

- 顶栏含 `safe-area-inset-top`；底部固定输入/操作区含 `safe-area-inset-bottom`。内容滚动区使用动态视口高度，不让浏览器地址栏变化造成关键按钮消失。
- 全局导航抽屉、AI 全屏层、历史会话抽屉一次只出现一个顶层浮层；支持关闭按钮、遮罩点击、Escape，关闭后恢复焦点与背景滚动。
- 可点区域建议至少 44×44 CSS px；文字输入字号至少 16px。长标题/路径截断且可查看全称。页面可纵向滚动，避免用全局 `overflow-x:hidden` 掩盖真正的溢出。
- 手机/平板横竖屏切换保留当前路由、已输入文本和滚动位置；重新计算可视高度。对于带未保存内容的离开操作，先提示。

## 4. 分页面需求与交互

### 4.1 欢迎页与工作台（P0 / P1）

欢迎页手机端标题、视觉与“进入工作台”操作均在首屏或正常纵向滚动内可达；Three.js 画布随 resize / orientation 更新，渲染失败或低性能设备显示静态背景，主按钮仍可操作。现状是点击欢迎视觉进入工作台，不是账号登录；按钮文案不得写“登录”。

工作台 Hero 的五个 tab 在手机端横向滚动，当前项完整可见；输入框与提交按钮纵向排列。待办先显示加载，再显示数据/空状态/错误；新增、完成、删除保留服务端真实返回，失败时保留原值并提示重试。工具矩阵、工作流、资讯与项目资源采用单列卡片；静态展示与外部链接用文案/图标识别，不暗示点击即执行 AI 工作流。Agent tab 提交时预填 `/chat`，由用户点击发送，避免无意启动请求；站内文章 tab 如要保留 `/blog?keyword`，博客应消费该参数并展示清除筛选动作，否则首期移除“站内检索”承诺。建议实现前者。

### 4.2 AI 侧栏与独立聊天（P0）

顶栏 AI 点击打开全屏 `RemoteChat`，顶部显示“AI 助手”及关闭，底部输入区始终位于软键盘上方。会话历史在手机端由抽屉进入；发送中可停止，网络断开时保留已输入/已返回内容并显示“重试”。关闭并重开当前页时保留该组件既有会话状态；跨刷新持久化以现有接口能力为准。`RemoteChat` 开发环境不能写死 `localhost`，应走同源代理或环境配置；手机局域网联调需验证真实请求。

独立 `/chat` 保留独立会话实现：手机顶栏有返回、历史、新对话；历史抽屉选中后收起；消息区可滚动，输入区固定底部并适配软键盘。工作台带 `prompt` 进入时输入框预填但不自动发送；刷新/分享链接仍能看到预填文本。空白会话显示引导，发送时显示流式进度，停止/失败后可重试；切换历史时若输入未发送，保留草稿或明确提醒。两种聊天入口的历史**不承诺互通**，原型用说明标出。

### 4.3 技能知识库（P0）

手机进入后显示顶部“选文档”按钮与当前文档名，目录为左侧抽屉，默认收起。首次无选中文档显示空状态；目录加载、无内容、出错分别显示加载提示、空提示、错误与重试。选择后抽屉收起、加载正文；预览占剩余可视高度，iframe 自身滚动，不因父容器 `auto` 高度塌陷。工具栏首行放名称和选文档，次行放预览/源码及更多操作，路径过长截断。桌面仍为树目录 + 正文分栏。

开发环境若编辑能力可用，手机编辑态使用“预览 / 源码”两 tab，同屏只展示一项；源码区可完整输入，底部固定保存/取消。保存中禁用重复提交；保存成功提示并更新预览；保存失败保留脏内容。切换文档、离开编辑、关闭页面前有未保存内容时提示“继续编辑 / 放弃修改”。生产编辑锁由构建实测决定；锁定时不展示可点的编辑入口，并说明“当前环境仅支持预览”。移动端不对 iframe 内容做强制缩放作为默认方案，因为交互与文字可读性会受损；若具体 HTML 文档本身不响应式，列出文档清单另行改造，当前页可提供“在新标签打开原文”。

### 4.4 博客、艺术廊、个人页（P1）

博客去掉 960px 最小宽；推荐/最新/我的 tab 不被顶栏覆盖，文章卡片手机端图文纵排。`/blog?keyword` 显示搜索词与清除筛选；无结果、接口失败分别说明。已有 mock 初始文章与 `/api/articles` 返回内容必须在页面上区分来源或由产品决定是否隐藏 mock，不能将示例视为用户真实文章。编辑器 Markdown 工具栏横向滚动，发布弹窗在 320px 内完整显示，草稿保存/发布成功和失败都有反馈；未保存离开需提示。

艺术廊沿用已有断点，手机重点验收图片/视频弹窗关闭、左右滑动与滚动锁释放，示例内容标明“展示”。个人页在 769–1023px 及手机端允许纵向滚动，内容不能因固定高度或 `overflow:hidden` 裁掉。

### 4.5 睡眠空间（P1）

正式手机导航只保留新标签外站入口，不把 `createSpace` iframe 作为默认访问路径。若既有深链访问 iframe 路由，提供“打开睡眠空间网站”与“返回工作台”，避免 iframe 盖住顶栏；保留路由需按导航高度计算可视区。外站本身的手机体验不属于本期交付，联调记录问题和负责人。

## 5. 状态、依赖与异常处理

| 流程 | 默认/加载 | 空/错误 | 成功/离开 |
| --- | --- | --- | --- |
| 菜单/AI 层 | 默认关闭；打开后锁背景滚动 | 焦点未落入层或返回后滚动锁未解除均为缺陷 | 选路由或关闭后恢复焦点/滚动 |
| 工作台待办 | 骨架/加载文案，请求 `/api/agencies` | 空数据给新增入口；失败给重试，不能当空数据 | 操作成功更新列表，失败保留当前项 |
| 独立聊天 | 空会话/流式中 | 网络失败、停止、历史为空分别提示 | 消息发送、切会话、返回工作台；草稿明确处理 |
| AI 侧栏 | 全屏打开；历史单独抽屉 | API 地址错误/断流给错误与重试 | 关闭回原页面，不丢未发送输入 |
| 知识库 | 目录与正文分开加载，接口 `/api/skillKnowledgeBase` | 目录失败、文档失败、iframe 内容不响应式分别处理 | 选择、预览、编辑保存/取消；脏内容离开确认 |
| 博客 | 本地 mock 与 `/api/articles` 接口状态分别识别 | 筛选无结果、请求失败、发布失败不混淆 | 列表/编辑/发布，返回时保留或确认草稿 |
| 外站 | 新标签打开 `space.ltbot.top` | 弹窗被拦截提供手动链接；外站加载失败由外站处理 | 原站页面继续保留 |

本 PRD 不新增 API 字段。接口地址、鉴权、跨域、生产编辑锁、`/chat` 的流式能力以现有前后端联调确认；其中知识库和外站内容不能只靠 ltbot CSS 解决。性能先记录移动端首屏基线（JS/CSS 体积、LCP、长任务），再按路由拆包/图片懒加载降低负担；不凭现有清单中的估算数字设虚假达标值。

## 7. 验收用例

1. 在 320、375、414、768、1024、1440px 逐路由断言 `document.documentElement.scrollWidth <= innerWidth`；允许组件内部明确设计的横向 tab/工具条滚动。包括欢迎、工作台、知识库、独立聊天、博客列表/编辑器、艺术廊、个人页及睡眠空间承接页。
2. 375px 工作台打开菜单、切知识库、返回；顶栏无文字竖排/裁切，焦点和滚动恢复。AI 入口轻点一次打开全屏，关闭后原页滚动可用；拖拽行为仅 PC 保留。
3. 工作台提交 Agent 指令后 `/chat` 预填同一文本、未自动请求；点击发送出现用户消息与流式/错误反馈。历史抽屉可切换与关闭，键盘弹出后发送按钮仍可点。
4. 知识库目录成功、空、失败三种模拟结果可区分；选文档后预览高度不塌陷。开发环境源码编辑、保存失败、脏内容离开提示均通过；生产构建编辑锁验证。选取至少一篇宽文档，确认 iframe 内部是否另有横向滚动，并记录来源文档。
5. 博客筛选/无结果、文章卡片、Markdown 工具条、发布弹窗在 320px 不溢出；API 错误不显示成“暂无文章”。工作台待办在请求失败时可重试，不能误报完成。
6. 横竖屏切换、浏览器地址栏收起/展开、刘海/底部手势区、软键盘、弹窗连续开关 3 次均不遮挡关键操作。外站弹窗被拦截后手动链接可达。PC 1024/1440px 原有导航、聊天、知识库及博客操作通过。

建议埋点（需现有统计方案确认）：`mobile_nav_open`、`mobile_ai_open`、`mobile_chat_send`、`kb_doc_open`、`kb_preview_error`、`blog_publish_result`，只记入口、路由、结果与设备宽度，不收消息、文档正文或个人数据。

## 8. 待决问题与风险

- **导航入口**：建议手机抽屉纳入博客与艺术廊，因为目前顶部导航没有这两个入口，但工作台可到达。此为信息架构变动，需用户评审确认；不确认前研发可先实现抽屉容器与现有四项。
- **AI 入口**：建议手机顶栏 AI 取代悬浮球。若必须保留悬浮球，应修复 touch 事件并给内容避让区；两者同时常驻会造成重复入口。
- **知识库编辑**：现有 `process.env.NODE_ENV` 锁定逻辑需在实际生产构建验证；是否允许手机编辑取决于权限策略，不能仅凭前端开关决策。
- **博客示例文章**：mock 与真实文章混排可能误导用户。建议 UI 标明“示例”，后续再决定是否下线；本期不删除内容。
- **聊天关系**：独立聊天与 AI 侧栏是两套实现；若要求共用历史，需要单独定义会话迁移与接口，超出本次响应式改造。
- **联调环境**：本地 Vite 占用 6688 时，API 请求可能返回非 JSON。真实手机联调应使用明确代理与服务端地址，不把本地错误当线上故障。
