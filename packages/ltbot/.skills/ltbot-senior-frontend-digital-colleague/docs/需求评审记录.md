### 已确认事实与实施建议

- `/user` 曾在根路由和模块路由重复定义，现由 Layout 子路由承载。工作台 Hero 曾跳独立 `/chat`，现通过 Layout 打开 RemoteChat，并在会话初始化后写入 SDK 会话草稿键，不自动发送。
- 导航以 1023px 为移动断点；手机聊天为全屏层，知识库目录为抽屉，开发环境编辑器为预览／源码单页切换，生产编辑锁使用 Vite `import.meta.env.PROD`。
- 聊天与待办的移动入口统一同源 `/api`；外站睡眠空间使用 HTTPS 与手动打开链接，`/createSpace` 深链保留。
- 320、375、414、768、1024、1440px 浏览器视口检查四项页面及欢迎入口、深链，没有页面级横向溢出。模拟接口证明 Hero 预填时无 `chatAgent` 请求；实际 SSE、历史、保存及真机浏览器还需联调。

### P0/P1、待确认和工程影响

- P0：真实服务端及真机验收聊天发送一次 SSE、历史错误、待办失败和知识库保存失败；覆盖 iOS Safari、Android Chrome、微信浏览器的软键盘、安全区、旋转与外站跳转。
- P1：外站 iframe 策略与站点可用性依赖外站，手动链接作为本包兜底。
- 待产品确认：本轮无阻塞的产品决策；真实设备验收中若出现设计差异，按原型与需求再评审。
- 工程影响：`pnpm build` 改造前已有大量跨模块类型错误，本轮触及模块无新增诊断；Vite 产物另行验证。不要将模拟接口的浏览器检查记为后端联调完成。
- 下一步：接入可用后端并做真机矩阵，复核请求与会话顺序；存量类型问题单独排期。

### 已确认的工程事实

- `/workbench` 使用新工作台页面，旧工作台文件仍保留。
- 新工作台卡片大量来自本地静态数据；待办面板通过 `agency` Store 获取服务端数据。
- `/chat` 独立 ChatBot 和布局内 RemoteChat 侧栏是两套实现，不能用一套的联调结果代表另一套。
- 顶部“睡眠空间”打开外站；本包另有 iframe 页面。

### 评审建议与风险

- P1 建议：今后“统一 AI 助手”需求必须点名作用入口与会话兼容范围，否则验收含糊。
- P1 建议：工作台展示文案与真实功能要分层标注，避免用户以为静态工作流卡片已可执行。
- 待产品确认：独立聊天与侧栏聊天未来是并存、合并还是按不同场景分工；目前无授权结论。

### 工程影响与下一步

下一次涉及工作台或聊天需求时，以当前路由、组件和数据源为基线写验收；需要修改导航/路由时由产品确认目标体验。此条仅为现状评审，没有代码变更。
